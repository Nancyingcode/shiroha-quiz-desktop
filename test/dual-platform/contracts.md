# 阶段 A 平台契约

契约见 [contracts.d.ts](../../apps/web/platform/contracts.d.ts)，纯校验见 [validation.js](../../apps/web/platform/validation.js)。阶段 A 只定义边界和失败语义；尚未接入生产入口、浏览器适配器、保存队列或 Rust 命令。

## 接口与数据范围

所有平台操作采用 Promise 完成语义，业务失败返回 `Result`，初始化单独返回 `loading/ready/recovery_required`。UI 只有收到完成回执才能显示已保存；`pending` 表示待提交，`failed` 保留草稿并阻断依赖写入，`resolving` 表示必须查询结果。

| 接口 | 范围与约束 |
| --- | --- |
| storage | 初始化、按业务单位分页查询、普通提交、排他导入/恢复/重置、按操作 ID 查询结果；没有 SQL 接口 |
| files | 用户选择/拖放产生会话内、用途受限的授权令牌；读取/写入与释放授权；没有任意路径入口 |
| media | 暂存图片、按资源 ID 解析显示地址、释放显示租约；显示地址不进入交换备份 |
| configurations | 保存和读取非敏感服务配置；端点/账号改变使旧凭据绑定失效 |
| credentials | 设置、替换、删除及状态；没有明文 getter；取消记住必须先成功删除旧持久副本 |
| ai | 已配置服务、消息、请求 ID、题目复合 ID/指纹及取消信号；非流式响应保留关联标识 |
| webdav | 测试、列表、完整备份上传/下载及操作查询；对象 ID 由列表返回，不接收任意 URL、路径或鉴权头 |
| tasks | 查询、取消、订阅状态；进度事件不能包含凭据或正文 |

题目使用题库 ID 与题目 ID 组合定位，不要求跨题库题目 ID 唯一。题库、题目与记录保留合法 JSON 扩展，存储迁移不调用现有有损归一化。未知扩展不等于可执行命令；普通变更的操作字段严格限定。兼容过渡允许单独的 `replace_snapshot` 普通编辑载荷，导入/恢复/重置始终走排他接口。

## 提交与任务状态

`contractVersion=1` 独立于现有 Web 状态 `schemaVersion=1`、跨端版本 `1`、原生兼容 ZIP 版本 `3` 和富内容版本 `shiroha-web-rich-v1`。Web 导出的原生兼容 ZIP 使用 `schemaVersion=1/version=3`，Android 原生备份使用 `schemaVersion=3/version=3`，按容器 kind 分别识别，不能混用版本。旧格式的识别/转换属于共享导入层；本校验器接收已识别版本的兼容备份，不擅自升级、归一化或删字段。

实际选中题库导出分为单个题库对象与 `exportType=question_banks` 多库容器，由 `validateBankExport` 检查；它们不包含完整学习数据，不能混入完整恢复接口。历史 `shiroha_quiz_selected_banks` 备份容器仍单独支持。A2 的真实 Web 导出与 Android fixture 均直接约束这些校验。

每次提交包含操作 ID、预期修订号和业务变更。`freezeCommit` 生成独立深冻结副本，不冻结调用者原对象。适配器必须在入队时捕获载荷，并在实际提交时重新核对修订号。Web 修订检测不能提供 localStorage 跨标签原子比较交换保证。

重复操作 ID 返回 `duplicate_operation`，已知结果集合和待定操作集合都参与查重；调用方先使用 `getOperation` 查询确定结果，不能再次应用变更。已提交结果返回原回执；失败、取消和未找到分别处理；`pending/unknown` 均不能当作失败直接重写。适配器还必须持久化操作与载荷摘要，拒绝同 ID 不同载荷，并保证结果记录与数据提交一致。阶段 A 校验器仅使用调用方提供的当前修订和操作集合，不实现操作日志。

导入、恢复和重置要求此前所有提交已得到确定结果并取得排他所有权；普通写入遇到排他操作或失败依赖必须停止。普通变更及兼容 `replace_snapshot` 可以在已有待提交项时完成载荷校验，但必须由后续队列按顺序执行、提交前重新核对修订，校验通过不代表获准并发写入。覆盖恢复前的恢复快照、媒体落地和失败保全由后续适配器与 Rust 实现，前端类型与校验不能代替这些保证。

任务采用 `queued → running → succeeded/failed/cancelled`。终态不可回退，取消后的迟到成功必须丢弃；不同任务 ID 的事件不能互相覆盖。运行阶段可记录暂存、校验、提交和结果查询。提交开始后不能进入已取消状态或回到准备阶段；取消请求被接收不等于已经取消。结果不确定时任务保持运行并查询操作 ID，只有取得确定结果后才进入终态。

## 校验和安全边界

运行时校验拒绝不支持版本、畸形/未知操作、过期修订、重复操作 ID、循环/非 JSON 值与非法任务流转。输入按 JSON 数据对象处理，稀疏数组、隐藏字段、Symbol 字段、访问器和类实例明确拒绝，避免冻结后丢失语义或执行 getter。任务错误必须符合有限错误码及 `code/message/retryable` 字段约束；不接受额外请求头或系统路径字段。校验不修改输入，也不回显原始秘密。递归深度上限为 100，超限明确失败，不静默截断。

备份使用已知非敏感设置白名单，检查主设置、`webState.settings` 与历史 `webSettings`，并递归拒绝语义明确的凭据、服务令牌、鉴权头与凭据引用字段。允许题目 `options[].key`、分词扩展 `token` 和非敏感服务端点。字段黑名单是保守边界，拒绝输入不等于删除输入；未知设置应由后续导出层显式分类并提示，不能为通过检查静默删除用户数据。结构校验不是任意文本的秘密识别器；凭据写入口必须独立管理，导出器还须从批准字段构建载荷。导出字段中的绝对路径、内部媒体 URL 和端点内嵌凭据也会拒绝；实际路径、网络目的地、文件授权、关联完整性与数据库事务仍由对应平台内部校验。

能力状态为 `probing/available/unavailable`，不可用时有原因。PDF/OCR 的失败只能限制该功能，不能阻断核心题库初始化；原生能力不可用不能静默回退浏览器存储。

## 验证记录

`node --test test/dual-platform/contracts.test.cjs` 先因缺少实现而失败；A2 联调暴露 Android schema 区分、题库 JSON 入口、合法 token 字段与不确定结果终态等 5 项失败，修复后 21 项通过。独立复核再补跨端学习数组、待定操作 ID、任务错误边界与 JSON 保真共 5 项失败样例，修复后 **26 项通过**。覆盖非法变更、修订、重复 ID、冻结与失败阻断、恢复互斥、取消迟到、版本和凭据排除。类型用例位于 [contracts.types.ts](./contracts.types.ts)，含 Android schema 3 正例，检查明文 getter、SQL、系统路径、任意鉴权请求和恢复混入普通写入均不能通过编译；`npm run typecheck` 已通过。

这些是契约层的红—绿证据，不代表已有浏览器或桌面适配器通过相同场景；后续阶段必须对真实实现复用契约预期并验证故障恢复。
