# Shiroha Quiz Windows 原型

本工程使用 Tauri 2 和 WebView2，在独立 Windows 窗口中运行现有 Web 版。提供独立 release EXE，以及普通/离线 NSIS 候选安装包；尚未完成干净系统安装验收，不含代码签名或自动更新。

刷题顶部显示有效练习用时，可暂停并保留输入；暂停遮盖题目，继续后恢复。隐藏、最小化或暂时离开练习会暂停，返回后点击继续。考试仍沿用原倒计时，不提供暂停。

首页“最近训练”、训练记录和本轮结果页均可进入完整复盘，按本轮题序查看正确、错误及未作答题目，选错项与正确答案分别标识。新记录保留当时题目快照，旧记录只显示原有明细并说明缺失信息。复盘支持分页与重练错题；原题被删除或移动到不同分组时会提示重练范围限制。详见[计时与复盘设计](../../docs/superpowers/specs/2026-10-29-training-timer-review.md)。

## 环境要求

- Windows，以及较新的 Microsoft Edge WebView2 Runtime。
- Node.js 24 或更新版本、npm。
- Rust stable，使用 Windows MSVC 工具链。
- Visual Studio Build Tools 的 C++ 构建工具和 Windows SDK。

先在 PowerShell 中进入本目录：

```powershell
cd E:\Projects\shiroha-quiz-desktop\apps\desktop
```

仓库位于其他位置时，替换上述路径。本机 Rust 使用 `--no-modify-path` 安装；若当前终端找不到 `cargo`，且 Rust 安装在默认位置，可仅为当前 PowerShell 会话补充 PATH：

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
```

已经能够运行 `cargo --version` 的环境无需执行此步骤。

## 开发与构建

安装或更新依赖前，先退出使用本工程依赖的开发窗口和相关进程，避免 Windows 文件锁造成依赖目录不完整。仅停止能够确认属于本工程的进程。

```powershell
npm install
npm run dev
```

开发命令先生成前端资源，再使用 Tauri CLI 内置开发服务启动窗口，端口为 `51736`。不需要另行启动 Web 目录中的 Python 或 PowerShell 服务。
开发来源仅在调试构建中接受 `http://localhost:51736` 与 CLI 实际使用的 `http://127.0.0.1:51736`；发行版不接受这两个开发来源。来源仍须来自主窗口，不放行其他主机、端口或协议。

运行 `npm run test:dev` 可回归实际开发启动：脚本调用 `npm run dev -- --features native-test --no-watch`，使用临时题库、假凭据、阻断外网的隔离 WebView2 profile，检查原生初始化、页面解锁、导航、保存和重载。先关闭占用 `51736` 的开发实例；脚本不会终止其他实例。结果写入 `.reports/dev-smoke.json`，成功后清理本次临时数据，失败保留目录供排查。它不替代发行版的 `npm run test:desktop`，也不验证真实用户数据或真实凭据迁移。

构建 release 可执行文件：

```powershell
npm run build
.\src-tauri\target\release\shiroha-quiz-desktop.exe
```

输出路径为 `src-tauri/target/release/shiroha-quiz-desktop.exe`。构建命令使用 `tauri build --no-bundle`；首次构建需要下载 Rust 依赖并完成编译。

## 候选安装包与人工升级

```powershell
npm run build:nsis
npm run build:offline
```

两个命令均生成 x64 NSIS，目标为 `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/Shiroha Quiz_0.1.0_x64-setup.exe`。第二次构建会覆盖同名文件，需要在构建下一种制品前另存并记录 SHA-256。普通配置缺少 WebView2 时联网下载；离线配置嵌入完整 WebView2 安装程序，构建阶段仍需联网下载运行时。不得把普通包标记为离线包。配置遵循 [Tauri Windows 安装说明](https://v2.tauri.app/distribute/windows-installer/)。

离线 NSIS 仅包含 WebView2 离线安装程序，不包含 Codex 运行组件。首次使用 Codex Harness 仍需联网准备组件；已缓存且校验通过的组件可在本机复用，订阅登录与 AI 任务仍需联网。

默认安装到当前用户，无需为应用本身申请管理员权限。应用身份、生产数据目录和版本来源保持不变；安装配置拒绝版本降级。候选包未签名，尚不能作为已验收发行版。当前实际运行环境仅为 Windows 11 26200 x64、WebView2 155.0.4283.62；没有测得最低运行时版本，也没有验证 Win10 支持。

人工升级前在应用内导出完整 JSON/ZIP，核对备份可读取，再关闭应用并安装新版本。首次启动核对题库、图片、收藏和记录，失败时保留原数据及恢复点，通过应用内恢复入口修复；不要直接用旧 EXE 打开新版数据库。原型 EXE 到安装版、旧安装版到新安装版尚待独立 Windows 用户/VM 验证。

标准 NSIS 卸载界面的“删除应用数据”复选框默认不选中；要保留题库时不要勾选。系统凭据与应用数据是独立存储，移除已保存秘密应在卸载前通过设置清除并确认结果。卸载保留、改安装目录、中文用户名、无运行时断网安装和磁盘空间不足均仍需实机验收；构建成功不代表上述场景通过。

## 阶段 E 交互与文档验证

主窗口关闭时记录普通窗口尺寸与位置，下次只恢复位于当前显示器工作区内的有效位置；不可见位置回到默认居中。最大化/最小化状态不覆盖普通窗口位置。偏好文件为数据根下的 `window-state.json`，不属于题库交换备份。

导入页可以拖入单个受支持文件，走与文件选择相同的解析、预览和确认流程；桌面保持 HTML 拖放，用户交付的 File 不授予任意路径读取能力。原生系统打开/保存仍使用受控令牌。非文本编辑区域的 Ctrl+S（或 Command+S）触发保存；已有练习快捷键保留。WebDAV 恢复框提供初始焦点、Tab 循环、Escape 取消与焦点恢复。

OCR 支持取消、换源后迟到结果隔离及重新识别，完成和失败都释放 PDF/Worker/Canvas。单页渲染最多 16 Mi 像素（RGBA 约 64 MiB，不代表整个 OCR 内存上限），异常尺寸要求缩小扫描页后重试；保留原有页数限制。中文识别仍会出现题号误识别和字间空格，必须人工核对后再确认导入。

```powershell
npm run test:documents
npm run test:web-platform
npm run build:test
npm run test:desktop
```

文档回归自建文字 PDF、中文扫描 PDF、DOCX、XLSX，实际选择、解析、核对、导入、保存并重载检查题数和答案；外网阻断。扫描样本在测试中明确模拟人工核对，不声称 OCR 完全准确。真实系统文件对话框、长时间高负荷、所有覆盖层无障碍和正常发行制品仍有未验收项，详见[阶段验证记录](../../test/dual-platform/README.md)。Windows CI 与 Pages 独立，不发布或上传制品；托管 CI 不替代交互式 WebView2 验收。

## 资源与数据

[Web 页面](../web/index.html)和[应用脚本](../web/app.js)仍是唯一业务源码。资源准备脚本从 `apps/web` 生成本工程的 `dist`，排除 CMD、PS1、README 和 source map，并保留运行库与许可证；内联点击处理器仅在生成目录中转换。不要手工编辑或维护第二份 Web 源码。

开发和构建会自动准备资源。修改 Web 源码后，也可单独重新生成：

```powershell
npm run prepare:web
```

资源准备按内容增量同步：未变化文件保留时间戳，只更新新增或变化的资源，并清除失效文件和目录；输出缺失或损坏时会重新生成。每次仍执行离线资源、路径和链接校验及 bridge 打包，不依赖时间戳判断内容。资源准备与读取 `dist` 的构建应串行执行。该优化主要减少重复构建的资源写入，首次 Rust 编译与安装包下载、压缩耗时仍取决于环境。

应用标识固定为 `com.yiqiu.shirohaquiz.desktop`。桌面题库与学习数据使用 Rust 独占的 SQLite，图片按内容哈希保存，普通保存通过业务增量 IPC 提交；不会在原生服务失败时回退 localStorage 写入。桌面 AI/WebDAV 通过 Rust 的受控业务命令请求，HTTPS 使用系统证书校验，重定向限制来源与目录；Web 端仍保持浏览器请求及跨域限制。记住的 AI Key/WebDAV 密码写入 Windows 凭据管理器，未记住只在当前进程内存，页面只读取状态。MinerU 不属于本次迁移范围。

正常发行数据位于 `%LOCALAPPDATA%/com.yiqiu.shirohaquiz.desktop/local-data`，开发数据使用同级 `development`。目录内包含 `library.sqlite3`、WAL、媒体、恢复点和进程写入锁；不要在运行时只复制 SQLite 主文件充当备份。覆盖、重置及恢复前会先创建并验证包含媒体的恢复点；设置页可读取并选择恢复点。恢复点和未引用媒体目前均保守保留，不自动删除，磁盘空间不足时操作失败并保留原数据。

原生打开/保存通过系统对话框选择文件，页面仅获得有时效的分块访问令牌。保存先写同目录临时文件，回读验证大小与 SHA-256 后替换目标；取消或替换失败不报告保存成功。共享 JSON/ZIP 仍是交换格式，数据库文件不是跨端导出格式。

开发与生产来源不同，数据互不共享。同来源旧原型数据在空目标库启动时显示迁移确认，迁移保留旧主状态、独立配置、凭据和未知键；数据成功后 SQLite 成为活动来源。D2 接续迁移时校验已落库配置与记住选项，写入并验证对应原生凭据后才清理该旧值；失败保留旧值并提供独立重试，不重跑题库迁移。目标已有数据时不自动覆盖；需要合并旧数据时先导出备份再主动导入。外部 Web 数据须在原浏览器导出完整备份，再在桌面窗口导入；应用不会扫描浏览器资料目录。

首页读取题目索引和记录摘要，不读取全部正文与图片；题库预览、错题和收藏每页 50 条，练习/考试读取选定题目，历史记录展开时读取明细。统计和跨库选题仍覆盖全部索引；完整导出读取全部正文。离开页面释放未修改且未被练习/考试使用的题目缓存。

数据库损坏时，启动恢复页提供“查找本机恢复点”和“选择兼容备份修复数据”。确认后先在 `generations/<UUID>` 建立并校验恢复副本，再原子更新 `active.json`；原数据库、WAL、媒体和旧活动代均保留。请保留完整数据目录，不要只删除主库强制初始化。设置页也提供恢复入口，健康数据库继续使用常规恢复点恢复。验证结果和发行环境边界见[阶段 C 记录](../../test/dual-platform/README.md)。

## 雾蓝一体视觉

桌面使用[雾蓝一体样式](./frontend/desktop.css)：导航与正文共用连续浅蓝背景，首页以留白和细线区分版本信息、快捷入口及统计，题干与表单保留浅色阅读面。普通页面收起导航时，正文随 220ms 过渡向左移动并扩展可用宽度，展开时恢复；系统启用减少动态效果时直接切换。页面与内部滚动区域统一使用透明轨道、细灰圆角滑块，悬停时加深。练习和考试沿用既有专注模式，临时展开导航时使用实色背景。

资源准备脚本在共享样式之后注入本地 `desktop.css`，并为生成页面添加桌面标识。仅维护 `frontend/desktop.css`，不要编辑 `dist/desktop.css`；Web 与 Android 的共享源码不变。生成前会检查样式文件和 HTML 入口，输入无效时保留既有输出。范围与验收记录见[视觉设计](../../docs/superpowers/specs/2026-10-23-desktop-mist-blue-design.md)和[实施计划](../../docs/superpowers/plans/2026-10-23-desktop-mist-blue.md)。

全局消息、保存/错误提示与窗口操作提示使用统一的雾蓝阅读面、细边框和轻阴影，成功、提醒及错误以低饱和色条区分。通知正文支持长文件名换行，关闭按钮保留键盘焦点；底部错误提示保留重试与恢复入口，长内容可滚动。

桌面 smoke 会实际调整本次测试子进程的原生窗口，覆盖 1280×860、900×640 和 1600×1000 的首页、导入、练习及考试，记录实际 WebView2 视口。它检查页面溢出、菜单边界、收起与展开时正文的位移和过渡、减少动态效果、滚动条与滚动交互，以及专注模式按钮可达与退出恢复，截图写入 `.reports/mist-blue-*.png`。

### 沉浸式标题栏

标题栏与雾蓝背景连续融合，图标和应用名仅在顶部出现，左侧导航从「首页」开始。标题空白处可拖动，双击最大化或还原；右侧保留最小化、最大化/还原、关闭按钮，支持键盘操作。Windows 原生最大化按钮的悬停贴靠面板不保证与自定义按钮等价。

导航开关位于 `Shiroha Quiz` 名称右侧，使用固定的 36px 点击区和侧栏图标，展开、收起及专注模式中位置一致。悬停或键盘聚焦时显示「收起左侧导航／展开左侧导航」提示，沿用雾蓝底色与焦点轮廓。正文与导航保留 220ms 联动过渡，系统减少动态效果设置仍优先；保存期间沿用原有交互锁。位置方案及验证见[设计](../../docs/superpowers/specs/2026-10-24-desktop-navigation-toggle-position.md)和[实施计划](../../docs/superpowers/plans/2026-10-24-desktop-navigation-toggle-position.md)。

标题栏模板与脚本维护于 `frontend/titlebar.html`、`frontend/titlebar.js`，由资源准备脚本注入生成页面。标题栏使用拖动、最小化、最大化切换、最大化状态读取和关闭五项权限；阶段 C 另逐项增加受控本地数据与文件业务命令，阶段 D 增加服务凭据、服务请求及关闭协调所需事件与窗口销毁权限。官方桥接打包为本地脚本，保持 `withGlobalTauri: false`，CSP 与存储来源不变。视觉设计及历史验收记录见[标题栏设计](../../docs/superpowers/specs/2026-10-23-desktop-immersive-titlebar.md)和[实施计划](../../docs/superpowers/plans/2026-10-23-desktop-immersive-titlebar.md)。

修改窗口配置后，请停止并重新运行 `npm run dev`，让原生窗口和生成资源一起更新。

## 验证

在本目录运行：

```powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run build:test
npm run test:desktop
```

`npm test` 包含资源过滤、内联事件转换和路径安全检查。其中的 Windows junction 用例可能受到沙箱创建链接权限限制，应在正常本机终端运行并记录结果，不通过跳过断言掩盖失败。`lint` 同时检查本次工程文档的 UTF-8、代码围栏和本地链接。

`npm run test:desktop` 需要先执行 `npm run build:test`，使用 `target/native-test/release` 中带隔离 feature 的 EXE。测试根必须是 runner 本次创建且带隔离标记的临时目录，同时隔离 SQLite、媒体与 WebView2 profile，并默认阻止出站；网络用例仅允许 runner 创建的单一本机回环 mock 来源。正常 `npm run build` 不接受测试根覆盖，正常发行制品的运行验收须使用隔离 Windows 用户或虚拟机；本轮未执行该项。测试 feature 使用 fake 凭据，不访问系统凭据。单独的 Windows provider 测试使用随机测试命名空间和假凭据，结束删除；这不替代独立 Windows 用户验收。仅完成静态资源生成不能证明 PDF/OCR 已在 WebView2 中通过。

2026-10-23 已在本机 WebView2 155.0.4283.62 验证：7 项单元测试、类型检查、lint 及 release 构建通过；10 项实际桌面检查通过，包括启动不加载隐藏插画、进入导入页后插画正常显示、JSON 题库通过界面导入与练习、关闭重开后的题库保留、MathJax、PDF.js 真 Worker，以及本地 Tesseract 英文 OCR。OCR 样本为 Canvas 生成的 `TEST`，该结果不代表中文扫描 PDF 全流程或大文件性能已验证。测试截图生成于 `.reports/prototype.png`。

人工验收时，使用无敏感内容的小题库和 PDF 样本，检查独立窗口、练习、关闭重开后数据恢复，以及断网后的文字 PDF 导入和少量扫描页 OCR。再检查公式、DOCX/XLSX 导入与备份导出；控制台应无关键本地资源加载错误，生产环境不应执行 CDN 或内联脚本。

设计范围和后续边界见[设计文档](../../docs/superpowers/specs/2026-10-23-tauri-prototype.md)与[实施计划](../../docs/superpowers/plans/2026-10-23-tauri-prototype.md)。

## 启动优化与性能复测

桌面资源生成器移除 Web 版固定时长的启动遮罩及其专属预加载图片，非首页插画改用浏览器原生懒加载。首页图片保持即时加载；业务脚本、题库、持久化格式、Web/Android 源码均不改变，也没有通过关闭 GPU、裁剪功能或强制回收工作集降低读数。

在本目录运行 `npm run bench:desktop`，或指定可执行文件与报告路径：

```powershell
npm run bench:desktop -- .reports/baseline.exe .reports/performance-baseline-retest.json
npm run bench:desktop -- src-tauri/target/native-test/release/shiroha-quiz-desktop.exe .reports/performance-after.json
```

旧版 EXE 需要在重新构建前另行保留；接入原生数据后的比较制品必须均支持相同测试隔离，不要将正式原生构建直接传给 runner。脚本每版启动 5 次，第一次创建隔离 profile、后四次复用，保留默认题库与 1280×860 窗口；记录进程启动至页面 load 完成、启动遮罩消失的耗时，随后空闲 5 秒并采集主进程及全部 WebView2 子进程。进程创建时间和路径用于排除 PID 复用；脚本只关闭自己启动的窗口。成功时清理临时 profile，报告保存在 `.reports`，失败时保留诊断数据。本轮 C 未重跑性能基准，下表为原型阶段历史结果。

2026-10-23，Ryzen 9 5950X、32 GB 内存、WebView2 155.0.4283.62，旧版与新版在同一轮串行复测的中位数：

| 指标 | 旧版复测 | 优化后 | 差距 |
| --- | ---: | ---: | ---: |
| 启动至页面 load | 723 ms | 718 ms | 基本持平 |
| 启动至遮罩消失 | 3627 ms | 743 ms | 减少 79.5% |
| 完整进程树工作集 | 523.6 MiB | 510.9 MiB | 减少 12.7 MiB（2.4%） |
| 完整进程树私有提交 | 317.2 MiB | 285.3 MiB | 减少 31.9 MiB（10.1%） |
| 首页资源请求数 | 16 | 8 | 减少 50% |

优化后 5 次可见启动耗时为 737–961 ms，工作集为 503.0–515.2 MiB，私有提交为 274.8–288.7 MiB。启动改善主要来自取消固定等待，内存改善有限。工作集含可共享页面，跨进程求和会重复计数；私有提交也不等同驻留物理内存。测量开启 CDP 调试连接、未清空操作系统文件缓存，不能视为重启电脑后的冷启动或大题库/PDF/OCR 负载结果。

此前单独测得的旧版工作集中位数为 477.9 MiB，本轮为 523.6 MiB，反映进程工作集回收和系统状态的波动。本表使用同轮旧新版结果比较，不将节省量描述为所有环境下的固定值。初测、旧版复测及优化后原始记录分别为 `.reports/performance-before.json`、`.reports/performance-baseline-retest.json` 与 `.reports/performance-after.json`。

## 阶段 D：服务与凭据

私有 `service-bindings.sqlite3` 只记录绑定、暂存事务和迁移回执，不含秘密，也不进入题库导出或恢复点。保存配置采用暂存凭据、提交 C3 操作回执、启用绑定并清理旧副本的顺序；启动时据回执处理未完成事务。取消记住或清理失败会报错，不显示虚假的清除成功。凭据存储不可用时仍允许本地题库启动和恢复。

端点、账号或目录变化必须重新输入凭据；覆盖恢复、恢复点恢复和重置撤销绑定，即使恢复的是同一端点也不能自动复用旧秘密。旧系统副本可能保守保留以便失败恢复，但撤销后不能被业务请求读取。恢复后须重新配置服务。

原生 AI 保留非流式协议和共享人工确认流程，不自动重试收费请求。AI 请求/响应上限各 8 MiB，WebDAV XML 为 4 MiB、备份为 256 MiB，请求总超时 120 秒。WebDAV 仅允许探测、建目录、列举和指定备份对象读写；历史文件重试先核对远端内容，latest 更新失败保留已上传历史文件。上传中断显示结果待核对，先刷新远端再决定重试。

关闭窗口先检查保存、练习/考试和网络状态；取消请求后拒绝迟到结果。完整联调与尚未完成的发行环境验收见[阶段 D 验证记录](../../test/dual-platform/README.md)。

## CodeBuddy 账户与单题执行

桌面「AI 设置」先选择「使用 Harness」，再在 Harness 下拉框选择 CodeBuddy，即可显示对应账户面板。面板提供「登录 CodeBuddy」「打开授权页」「复制链接」「刷新状态」「取消登录」和「退出登录」。点击登录会打开官方浏览器授权页，完成后窗口自动显示个人账户登录状态；浏览器未打开时可重开或复制当前授权链接。

Harness 下拉框是唯一活动提供方，选择后自动保存；界面只展示当前 Codex、CodeBuddy 或 DeepSeek 的订阅区域。切换不会退出其他账户，也不会回退到其他提供方执行。DeepSeek 当前只展示未接入说明，不能登录或执行。CodeBuddy 支持连接测试、单题解析和追问；批量与导入任务会明确拒绝。保存选择失败时停止 AI 执行，可通过「重试保存选择」重试。

先准备 CodeBuddy 2.175.0 组件，再完成个人账户登录。组件从固定官方 ZIP 下载，校验压缩包和程序摘要，仅安装 codebuddy.exe；缓存与 Codex 分离。CodeBuddy 面板提供独立模型下拉框，默认 `deepseek-v4.1-flash`，也可选择 `hy4-preview`、`hy3` 或 `default`（服务端默认）。模型选择自动保存，切换提供方或重启后保留；保存未完成时不能执行旧配置，切换模型不退出账户。单次执行时限 120 秒；连接测试输出上限 1024 token，解析与追问上限 8192 token。不会自动重试或回退到 API。单题仅发送当前题目需要的文本及追问上下文，不发送图片；结果仍需人工核对，只在明确保存时写回解析。

执行失败时显示固定诊断码，可区分网络、输出上限、未知协议字段、不完整终态、组件输出和隔离通信等阶段。提示不包含请求正文或账户凭据；失败保留已有解析与追问草稿，不自动再次请求。

默认不勾选「在此设备记住登录」，授权只保留在当前进程，关闭后需要重新登录。主动开启后，令牌分片保存到 Windows 凭据管理器，应用私有数据库只记录保存与清理事务；不进入题库、恢复点或 WebDAV 备份。下次启动会向固定账户接口核验身份，通过后恢复登录，不会自动调用模型。关闭记住会删除保存的凭据并保留本次会话；退出、到期或明确拒绝授权会撤销并清理记录。首期不自动刷新令牌，过期后仍需重新授权。

保存失败时会明确提示并允许重试；退出清理失败时保持账户阻断，须重试退出，不能把未完成清理显示为已退出。断网时保留已保存记录，可「重试恢复登录」。不读取官方客户端的既有凭据。登录、恢复与组件准备不修改直接 API 或 Codex 设置；执行仍绑定当前账户和配置版本，旧结果不能越过退出、重登或数据恢复。CLI 在独立 Windows AppContainer 和 Job 中运行，明文凭据仅由宿主持有，宿主只允许一次固定模型请求。存储与恢复验证范围见[实施记录](../../docs/superpowers/plans/2026-10-28-codebuddy-login-storage.md)。

取消或退出后，旧授权即使稍后在浏览器确认，也不能恢复本窗口的登录。账户列表和所选个人身份在原生端核对，前端不接收令牌或个人标识。隔离桌面回归使用合成身份，不会打开真实授权页。2026-10-26 正式客户端的 `deepseek-v4.1-flash` 真实单题、追问及人工保存均通过：一次解析、一次追问，无重试；未保存时数据不变，保存后仅改变合成题解析及所属题库更新时间。当前结论覆盖个人账户和一道隔离自建题，实际 token/积分账单未核对。此前 `default` 的 2048 token 截断和 8192 token 下超时均保留为历史失败记录。客户端实现与实际验证见[正式执行计划](../../docs/superpowers/plans/2026-10-25-codebuddy-client-execution.md)，历史隔离与授权记录见[原生适配器计划](../../docs/superpowers/plans/2026-10-25-codebuddy-native-adapter.md)。

## Codex Harness：订阅执行现有 AI 任务

「AI 设置」可选择「直接调用 API」或「使用 Harness」。Codex 接收现有导入整理、批量核对、批量补解析、单题解析与追问；结果仍需人工核对与采纳，不增加学习助手侧栏，不自动判题或保存解析。CodeBuddy 支持范围见上节；DeepSeek 尚未接入执行。

首次配置步骤：

1. 在「AI 设置」选择「使用 Harness」，并在下拉框选择 Codex。程序自动准备[官方 Codex 0.163.0 Windows x64 组件](https://github.com/openai/codex/releases/tag/rust-v0.163.0)，首次从 GitHub 下载约 341 MB（341270320 字节），界面显示准备状态和字节进度。等待组件就绪；默认流程无需手选程序、手动检测或先点保存。
2. 点击「登录订阅」。程序先保存所需 Harness 配置，再显示官方地址和设备码；复制到自己的浏览器完成登录。设备码约 15 分钟有效；账户或管理员可能需要先启用设备码登录。应用会自动刷新状态，也可点击「刷新授权状态」。首版仅开放通过工具隔离验证的 `gpt-6.1-sol`；可选不代表订阅一定有访问权限。
3. 点击「测试连接」执行固定小任务。它会消耗订阅用量；完整结果通过校验后才显示成功。自动准备和登录不会自动发起模型测试。之后从原有业务入口主动发起 AI 任务。

组件缓存在本应用数据目录 `ai-execution` 下，复用前仍核对固定大小和 SHA-256；文件不进入题库或跨端备份。应用不会查询或静默更新到最新 Codex；版本升级须随应用重新验证协议、模型与工具边界。取消或准备失败保留原执行配置和已有授权，清理本次未完成下载；需要时点击重试，不会靠普通状态刷新自动重启下载。直接 API 的配置与凭据仍独立保留。

组件下载跟随 Windows 当前用户的手动系统代理：启用时使用对应协议的代理，未配置时直连，并遵守域名及本地地址绕过规则；启动器的代理环境变量不会覆盖系统开关。修改代理后点击「重试准备」即可重新读取配置，无需重启应用。代理连接失败会明确提示，不会自动绕过代理直连；固定官方地址、TLS 证书和文件哈希校验仍保留。下载器支持统一或分协议的静态 HTTP/HTTPS 代理，尚未实现 PAC/WPAD 自动解析；只有 PAC 配置时会提示检查手动代理设置。

Codex 运行时另由固定官方版本的系统代理实现处理认证与模型请求，启用 `features.respect_system_proxy=true`，HTTP 与 WSS 共用系统路由。官方 Windows 实现支持手动代理及 PAC/WPAD；选定代理后连接失败不会再尝试直连。系统代理发现不可用时，官方实现会依次尝试环境代理和直连；本应用仍清空继承环境，不带入启动器的代理变量。上述行为已核对固定版本源码，本机代理修复后的模型连接及 PAC/WPAD 实际环境尚待验证。

「高级设置」保留程序路径、版本、手动选择和检测，供已有本地安装或排查使用。旧版保存的非空程序路径继续作为自定义来源，不会被自动替换；自定义程序也必须是同一固定版本和摘要，当前桌面内置 alpha 或其他版本不能代替。点击「恢复自动管理」可显式切回受管组件，准备成功后才采用新来源。许可证原文与固定来源见[Codex 第三方说明](third-party/codex/README.md)，管理边界见[组件管理设计](../../docs/superpowers/specs/2026-10-25-managed-codex-runtime.md)。

登录中途取消或失败后，先点击「退出订阅登录」清理未完成的授权，再重新登录；即使设备码已在浏览器确认，也不会自动采用一个未确认完成的登录结果。

Harness **仅使用订阅登录**，不接 API Key、不读其他 Codex 产品的全局账户、不自动改用 API 计费。认证使用官方 CLI 的加密凭据存储：加密密钥由 Windows 系统凭据保管，授权内容加密保存在本应用专属 `CODEX_HOME`（`ai-execution/profile`）内；不允许退回明文 `auth.json`。密钥与密文均不进入题库、业务数据库、日志或跨端备份。普通关闭保留授权；「退出订阅登录」只清理此专属环境；切换账户先退出当前授权。清除 Harness 配置或退出登录后仍保留 Harness 执行方式并显示不可用，需明确选择并保存才切回直接 API。

2026-10-25 的隔离假授权复现确认：将较长 OAuth 内容直接写入 Windows 单项凭据会超过容量限制；改用官方加密存储后，长令牌的登录、独立进程读取状态及退出均通过，未生成明文 `auth.json`。随后用户完成真实订阅登录，正常重启后授权仍保留。补齐运行时系统代理后，固定模型 `gpt-6.1-sol` 的真实连接测试、当前一道单选题解析和一次追问均通过；追问更新了解析草稿，未写回题库或提交作答。解析期间只读采样确认组件存在到本机代理的已建立连接。该结果仅覆盖当前账户和手动代理环境，不代表所有题型或 PAC/WPAD 环境已完成验收。

每次只发送该任务需要的文本、参考答案、当前作答及相关追问上下文，不发送题库文件或图片。Codex 无命令、文件补丁、浏览器、插件、子代理或提问工具；固定程序摘要、受限模型目录与配置共同约束权限。只读沙箱本身不是工具隔离。配置和登录不进入跨端备份；恢复或重置数据会取消任务并要求重新检测。超时、取消、异常退出不由宿主重新发起生成；Codex 自身传输层仍可能重连，不能将此描述为所有网络重试均为零。

本地工具与协议验证使用假订阅令牌、回环服务和隔离数据；桌面验收使用编译期 fake Harness，脚本覆盖默认自动准备与登录、原 API 配置保留和高级来源切换；下载回归使用小型测试字节流。进程树回收另由真实子进程测试覆盖。这些隔离自动化测试不操作真实账户或消耗真实订阅，也未验证干净系统安装；经用户授权的真实订阅验收进度见上文。这里使用官方 CLI 原有设备码登录，未实现第三方 Sign in with ChatGPT 客户端注册；公开分发前需另行确认认证方式与真实账户行为。具体依据、摘要和验收结果见[设计](../../docs/superpowers/specs/2026-10-24-ai-harness-execution.md)、[实施计划](../../docs/superpowers/plans/2026-10-24-ai-harness-execution.md)与[组件管理计划](../../docs/superpowers/plans/2026-10-25-managed-codex-runtime.md)。
