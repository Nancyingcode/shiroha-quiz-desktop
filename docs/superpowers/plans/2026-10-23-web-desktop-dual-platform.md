# Shiroha Quiz Web 与 Windows 桌面双端实施计划

日期：2026-10-23

依据：[已确认的双端设计](../specs/2026-10-23-web-desktop-dual-platform-design.md)。本文将设计的 A—E 五个阶段拆成可执行任务，不重新选择产品架构。

状态：用户授权执行阶段 C，并明确保留 D2 凭据联调待办。**A/B 已完成；C8 界面按需查询、损坏数据库恢复入口及本机可执行的故障回归已补齐；D/E 未实施。** C 的本地数据实现和隔离测试版闭环见[阶段验证记录](../../../test/dual-platform/README.md)。C7/C9 的 D2 联调、隔离 Windows 用户/VM 中正常发行制品及人工系统对话框验收仍独立保留，不把测试 feature 的运行结果等同正式环境验收。

## 1. 实施范围与工作约定

- Web 保留在线静态站和现有 ZIP 使用方式；桌面首期支持 Windows 10/11 x64，具体系统构建号和 WebView2 版本以实际验收矩阵为准。
- `apps/web` 是唯一业务源码；桌面只增加平台适配、原生服务和资源生成步骤，不维护第二份业务页面，不整体迁移前端框架。
- 第一轮完成异步平台契约、SQLite/媒体、迁移恢复、原生文件、AI/WebDAV、Windows 凭据、运行验证和安装包。
- 本轮不增加 Win7、32 位桌面包、Web IndexedDB/PWA、自动双向同步、自动更新、MinerU、完整未交卷会话恢复、托盘、开机启动、文件关联或多窗口。
- Android 原生互通通过既有格式和 fixture 验证，不直接改 Kotlin 业务；Android Web 壳的旧 assets 不自动同步。
- 现有 npm/Cargo 包管理器、Rust edition、应用标识和存储来源保持稳定。新增依赖前说明用途、许可、维护、体积和工具链要求，随后才修改相应清单与锁文件。
- 每个行为任务执行“失败测试或可重复复现 → 最小实现 → 通过相关测试 → 必要整理”。现有行为的特征测试应先验证基线，不人为制造失败；新行为必须有能区分缺实现或错误实现的断言。
- 不擅自 commit、push、创建 PR、上传或发布制品。本文不安排自动提交；未来需要多任务合并时遵循根规范的独立提交与整合要求。

本计划中的新增文件名和新测试入口均标记为“拟新增”。实现时可按现有代码粒度调整，不为满足目录示意创建空模块或通用框架；调整后同步任务记录。

## 3. 阶段总览与依赖

| 阶段 | 任务 | 主要交付 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| A：基线与契约 | A1—A4 | 行为/格式 fixture、接口与失败语义、检查入口、环境记录 | 核心行为有可重复预期，平台接口和检查范围清楚 |
| B：Web 适配 | B1—B5 | 浏览器适配器、异步初始化和有序提交、共享文件/网络入口 | Web 回归通过，桌面原型继续运行，无未处理保存 Promise |
| C：桌面本地数据 | C1—C9 | 原生隔离、IPC、SQLite、媒体、文件、备份、迁移、增量读写 | 两种迁移和失败恢复通过，重启数据一致，无浏览器隐式回退 |
| D：网络与凭据 | D1—D5 | 服务配置、系统凭据、原生 AI/WebDAV、取消与联调 | 协议兼容、凭据不泄露、任务终态正确 |
| E：稳定性与安装 | E1—E6 | 文档处理、桌面交互、性能、安装包、CI 和交付记录 | 双端与 Win10/11 验收完成，制品可复现构建 |

依赖顺序：

```text
A1 → A2/A3 → A4 → B1 → B2 → B3 → B4 → B5
                                         │
                                         ▼
                                     C1 → C2
                                          ├─ C3 → C4 → C5 → C6 → C7 → C8 → C9
                                          └─ D1 → D2 → D3/D4 → D5
                                                   └────────→ C7 凭据迁移联调
                                           C9 + D5 → E1/E2 → E3 → E4 → E6
                                                        E5 CI 可提前分段接入 ─┘
```

A2/A3 可分工核对，但接口必须由 fixture 约束。B 阶段按业务切片推进，不批量替换后集中修复。C/D 在 C1/C2 提供隔离、命令和任务基础后可并行；C7 的完整迁移验收必须等待 D2，C/D 最终共同验收后才能形成正式升级候选版本。

D2 的实际服务配置联调依赖 C3，D4 的恢复联调依赖 C6；等待期间仅用相同契约的 fake 实现开发各自单元测试。D2 的凭据能力先独立完成，再与 C7 迁移协调器接入，避免形成互相等待的任务环。

`app.js`、契约定义、命令注册、权限配置和锁文件设单一整合责任，避免并行任务互相覆盖。并行适合独立 Rust 模块、fixture、文档和测试；不能在多个任务中各自改写同一保存流程。

## 5. 阶段 B：Web 适配与异步保存

### B1. 引入平台入口，保持双端可启动

**涉及位置：** `apps/web/index.html`、`app.js`；拟新增 `platform/index.js`、`platform/browser.js`；桌面资源生成器及其测试。

1. 在业务启动前创建平台服务，Web 默认使用浏览器实现。平台实例由入口提供，业务代码不散布 `isDesktop` 和 Tauri 导入。
2. 第一轮保持普通脚本加载；若桥接需要 npm 构建，仅将桌面桥接打包为本地脚本，不给静态 Web 增加无必要构建要求。
3. 资源生成器为后续桌面入口预留明确注入点，验证顺序、输出唯一性、重复生成和源目录不变。
4. 同步 AI harness 的启动等待及实际脚本装载，保留只读测试观察能力，不把可修改真实状态的测试后门放进生产页面。

**先写失败测试：** 平台未就绪不得进入业务；Web 不加载 Tauri 包；桌面资源没有裸模块引用、远程/内联可执行代码；生成清理不能越界。

**验收：** 现有静态站、Web ZIP 启动方式及原型 EXE 均可进入核心页面，既有生成器安全断言仍有效。

### B2. 改造加载和初始化

**涉及位置：** `loadState()`、`migrateState()`、`upgradeState()`、`ensureDefaultBank()`、`init()`；浏览器适配器；拟新增 `test/dual-platform/startup.test.cjs`。

1. 改为显式异步启动，全部顶层绑定创建完毕后再开始初始化；保留初始化顺序和现有事件绑定语义。
2. 区分无数据、空题库、损坏 JSON、拒绝访问、过新格式和服务不可用；首次使用或用户确认的全量重置成功后按现有规则初始化默认题库。删除全部题库所设置的 `suppressDefaultBank=true` 必须保留，不能与全量重置混淆。
3. 加载失败提供重试/恢复入口，禁止编辑、默认题库回写及静默清空。
4. 无损读取与题目解析归一化分开；保留合法富字段/扩展，不改变现有题型判定和评分规则。

**先写失败测试：** 延迟加载时点击不能写入；损坏原值保持不变；删除最后题库后保持空库；全量重置成功后重新初始化默认题库；可选 PDF/OCR 失败不阻断首页。

**验收：** 启动状态可观察，失败不覆盖原数据；普通题库与富字段 fixture 重启后保持。

### B3. 建立提交队列并逐组改造保存调用

**拟新增：** `apps/web/platform/save-queue.js`、`test/dual-platform/save-queue.test.cjs`；修改 `app.js` 的 A1 调用清单。

1. 先实现队列、冻结载荷、修订号、操作结果及失败暂停；浏览器实现仍将兼容状态写入原 localStorage 来源和键。
2. 先改设置/选中题库等小范围入口，再改题库增删改、错题/收藏、记录，最后改导入恢复、AI 保存和考试提交。
3. 所有依赖持久化成功的提示、编辑态清理、按钮状态和下一步操作都等待提交；事件处理捕获异步错误，不只保留同步 `try/catch`。
4. AI 解析保存、题库编辑和恢复保留草稿及失败前数据；失败操作不能用旧全量快照抹掉之后的用户编辑。
5. 导入、覆盖恢复和重置排他执行；等待先前提交达到确定结果，再暂停新编辑并提交。取消/失败后恢复正确入口。
6. Web 检测外部存储修订和变更事件后阻止已知过期写入；明确不提供 localStorage 跨标签原子比较交换或并发编辑保证。

调用清单至少覆盖以下组，实施时记录每项迁移结果，不只替换两个保存包装函数：

| 调用组 | 现有入口举例 | 专项要求 |
| --- | --- | --- |
| 配置/选择 | `bindEvents()`、AI 设置保存/清除、WebDAV 配置、侧栏状态 | 主状态之外的独立存储项也有明确平台归属 |
| 题库/题目 | `confirmImport()`、`appendImportToBankV5911()`、`savePracticeEditQuestionV120()`、`saveBankEditSessionV45()`、重命名/复制/合并/去重/删除 | 保存失败保留编辑会话、预览选择和报告；预览中的 `saveEditQuestion()` 不提前持久化 |
| 学习数据 | `finishPractice()`、`submitPractice()`、简答自评、收藏/错题按钮 | 延迟或失败不重复计数，已完成提交与界面状态一致 |
| 考试提交 | `submitExam()` | 现有先标记 submitted 再保存的路径要支持失败重试，并阻止重复记录；不扩展为完整续考 |
| 精细回滚 | AI 解析保存、本地备份恢复、WebDAV 恢复 | await 后捕获失败，局部补丁只影响所属操作，不回滚之后的编辑 |

**先写失败测试：** 两次连续编辑延迟不同、首个保存失败、失败后新编辑、重复点击/重试、恢复与普通保存交错、重置失败不刷新或假报完成、quota、外部标签修订变化、考试提交重复触发。

**验收：** 清单中的每个保存调用有处理结果的归属；无未处理 Promise、假成功或旧回滚覆盖新状态；不新增完整考试草稿恢复。

### B4. 接入浏览器文件、媒体、网络和凭据适配

**先写失败测试：** 用户取消文件选择、下载失败、图片解析缺失、fetch 超时/取消、错误码、凭据切换记住状态、AI quota 回滚和切题隔离。

**验收：** 现有 WebDAV/AI 回归通过；用户能继续按原方式导入、导出和连接自定义服务。

### B5. 完成 Web 阶段回归与桌面原型衔接

**涉及位置：** 共享页面/样式、能力反馈、测试和 README；不增加新框架。

**验收：** B1—B4 全部通过，Web 与原型均可独立运行；C 阶段接入失败不会被静默解释成浏览器适配回退。

**先写失败测试：** 事务中途失败、磁盘满/只读、锁冲突、崩溃重开、重复操作、修订冲突、同题目 ID 不同题库、富字段保全、历史记录不随删库误删。

**验收：** Web 导出的包可在桌面恢复并反向导出供 Web 读取；差异有字段级解释，不能只比数量或文件大小。

### C7. 实现旧桌面原型与外部 Web 的两种迁移

**拟新增：** Rust `migration.rs`、桌面旧来源读取桥接和迁移测试；依赖 C3—C6，完整凭据迁移依赖 D2。

2. 同来源旧桌面通过页面读取自身主状态、独立 WebDAV 配置和迁移候选；明确开发/正式来源，目标已有数据时不隐藏覆盖。
3. 建立不含秘密的原始数据恢复快照，暂存媒体，事务写入并核对 ID、字段、数量、引用，迁移标记与业务状态同事务提交。

**先写失败测试：** 首次/重复迁移、空库、目标非空、损坏来源、独立配置遗漏、每阶段崩溃、磁盘满、凭据写入/删除失败和过新数据库。

**验收：** 原型升级与外部导入分别有 release 来源证据；旧数据保全、成功切换和失败重试均可重复验证。

### C8. 将整体快照过渡为业务增量和按需查询

**验收：** 桌面高频操作不再重写整库，首页无需载入全部图片；大库结果与基线一致。未完成此任务不能声称数据库性能改造完成。

**涉及位置：** 桌面 smoke、共享测试、原生故障测试、迁移操作说明。

1. 在隔离 release 环境按“创建/编辑 → 练习/考试 → 导出 → 重启 → 恢复”完成闭环。

3. 核对两种迁移、C7/D2 凭据联调和 Web 反向读取；清理逻辑不能删除快照或未完成任务的媒体。

**验收：** C1—C8 和关联凭据迁移通过；未验证场景单列，恢复步骤能从保留材料真正还原数据。

## 7. 阶段 D：原生网络与凭据

### D1. 建立服务配置与网络安全边界

**拟新增：** Rust `network/`、`service_config.rs` 与 mock 测试；桌面网络适配；依赖 B4、C1/C2。

1. 定义 AI/WebDAV 的受限操作和非敏感配置，校验协议、端点、账号、目录及响应体积；规范化规则用于凭据绑定。
2. 保持用户明确配置的本机/内网 HTTP 服务；HTTPS 检查有效，重定向逐跳核验，跨来源不带认证信息。
3. 不接受页面传任意请求方法、文件路径或鉴权头；WebDAV 远端对象必须处于配置来源和目录范围。
4. 网络测试在 Rust 侧使用 mock/出站限制；配置和错误使用假凭据测试脱敏，不依赖浏览器路由拦截原生请求。

**先写失败测试：** 无效协议、跨来源重定向、目录逃逸、超大响应、TLS 失败、错误泄密和未经允许的出站。

**验收：** 原生请求只能完成批准的业务操作，Web 仍使用浏览器请求与自己的跨域限制。

### D2. 接入 Windows 凭据存储及迁移

**拟新增：** Rust `credentials.rs`、fake provider 测试；修改共享设置 UI 的凭据状态交互。真实配置联调依赖 C3，独立凭据测试可先行。

1. 实现设置、替换、删除、状态查询；记住时保存系统凭据，未记住时仅在当前进程内存保存。
2. 使用服务类型＋规范化端点＋账号绑定凭据；换端点/账号及从备份恢复后重新输入或明确重新绑定，不自动发送旧秘密。
3. 取消记住时清除持久副本并验证结果；删除失败明确反馈，不能显示已经清除。
4. 提供供 C7 调用的旧值转移接口，先用假迁移来源验证“成功后才允许清理对应旧值”的结果契约；失败可独立重试，不影响已完成的数据迁移。真实同来源浏览器旧值的读取与清理在 C7 集成。
5. 共享 UI 不明文回读已保存秘密；输入替换值与“已配置”状态分离，不把占位符当真密钥保存。
6. 系统凭据与配置数据库没有共同事务。设置/替换按暂存、验证、绑定生效和旧值清理推进，分别记录失败并补偿；不能假定数据库回滚会撤销系统凭据写入，也不能为补偿将旧明文交给页面。保留、替换和明确清除的输入语义分别定义。

**先写失败测试：** 记住/取消记住、替换失败、删除失败、会话退出清理、凭据写入后配置提交失败、清理阶段中断、旧值迁移失败、恢复包换端点、日志/备份扫描。

**验收：** mock 生命周期、假迁移来源和隔离 Windows 用户下的实际凭据操作均验证；接口可供 C7 调用。真实旧原型迁移闭环由 C7 实现，在 C9/D5 联合验收，不作为 D2 的前置完成条件。

### D3. 实现原生 AI 请求

**涉及位置：** Rust AI 请求模块、桌面适配、现有单题 AI 测试 fixture；依赖 D1/D2。

1. 按现有请求/响应与非流式协议执行，在原生边界读取匹配凭据。
2. 保留现有格式降级触发条件、请求 ID、题目指纹、会话身份和迟到响应隔离；只在用户确认后写回题库。
3. 超时、取消、401/403/429、无效响应和结果不确定分别反馈；不对可能收费请求做不透明重试。
4. 用相同 mock 响应验证 Web/桌面业务结果，旧 AI 回归继续运行。

**先写失败测试：** 取消后返回、切题/切会话、格式降级边界、正文损坏、响应过大、保存失败保留草稿、重新生成失败不清旧内容。

**验收：** 真实 WebView2 到 Rust mock 的链路通过；不调用真实收费接口，不新增流式或自动写题功能。

### D4. 实现原生 WebDAV 备份与恢复

**涉及位置：** Rust WebDAV 模块、共享备份转换及面板；依赖 D1/D2、C6 的备份接口。

1. 保留现有历史文件命名、完整 JSON、哈希与 `latest.json` 协议，不新增自动同步。
2. 将列举、上传、下载恢复等限定操作映射到原生请求，校验返回 href 和路径范围。
3. 上传历史文件后更新 latest，分别报告失败与部分成功；重试前核对远端状态，不误报整次失败或重复上传。
4. 下载先限制大小、校验哈希和格式，再走共享预览及事务恢复；哈希不作为信任来源的证明。
5. 网络取消、暂存清理和窗口关闭遵守任务状态，不静默后台继续上传。

**先写失败测试：** 目录不存在、鉴权失败、跨目录 href、哈希不匹配、latest 更新失败、取消/超时、未知远端结果和恢复快照失败。

**验收：** 两端能通过隔离 mock WebDAV 手动备份/恢复同一组数据；部分成功状态、远端结果和本地数据一致。

### D5. 完成网络、凭据与任务联调

**涉及位置：** 保存反馈、任务面板/相关按钮、退出协调；C2 任务基础与 C7 迁移。

1. 对齐取消、任务 ID、修订号和操作结果；提交前取消，提交开始后等待确定结果，不显示“取消”却已经写入。
2. 请求期间修改服务配置、清除凭据或恢复备份时，明确旧请求归属并阻止迟到结果污染新状态。
3. 关闭窗口检查保存和原生任务；失败保留窗口，重试或用户明确放弃后才退出。实际交互细节在 E2 完整验收。
4. 回归 C7 完整迁移、两端网络行为、凭据绑定与禁止后台上传。

**验收：** C9/D5 联合通过；网络完成不等于数据提交成功，页面反馈能够区分两者。

## 8. 阶段 E：稳定性、安装与交付

### E1. 验证文档处理、离线资源与资源释放

**涉及位置：** Web 文档导入/OCR 流程、生成器、smoke；拟新增文档 fixture 和端到端用例。

1. 自建文字 PDF、含简体中文扫描页 PDF、DOCX、XLSX 和公式/图片样本，验证完整选择、解析、预览、确认、保存、重启及导出链路。
2. 阻断外网，确认 PDF Worker、OCR Worker/WASM/中英文语言包和公式资源来自随包资源；不以文件存在或英文 Canvas OCR 代替验证。
3. 按页处理并限制并发、像素、体积，先保留既有限额；取消/完成释放文档、Canvas、ImageBitmap、Blob URL、Worker 和临时文件。
4. 覆盖连续处理多文件、损坏文档、可选资源缺失和超限输入，提示可操作且不影响核心刷题。

**验收：** 两端分别记录完整文档链路结果；离线中文扫描 PDF、取消和多轮资源释放有实际证据。

### E2. 完成桌面交互、退出和无障碍

**涉及位置：** 主窗口配置、桌面适配、共享 UI、拖放管线与相关测试。

1. 完成原生打开/保存、窗口尺寸位置恢复；超出可见屏幕时可恢复，不引入多窗口。
2. 拖放接入 C5 的同一授权/校验/预览管线，验证 Tauri 与 HTML 拖放的关系，不能只切换 `dragDropEnabled`。
3. 完成应用内快捷键、焦点恢复、覆盖层焦点约束、错误通知及 reduced-motion；避免与文本输入操作冲突。
4. 验证正常关闭、保存中、存储失败、AI/WebDAV 运行中与未交卷考试。失败不静默退出，未交卷提示不宣称支持恢复续考。

**先写失败测试或可重复步骤：** 关闭中重复点击、取消退出、保存失败重试、任务提交临界点、拖入非法文件、键盘独立完成导入恢复。

**验收：** 单窗口交互可用，退出反馈与已提交数据一致，平台差异通过用户可理解的文案表达。

### E3. 性能对照与可靠性复测

**涉及位置：** `scripts/benchmark.mjs`、固定样本和报告方法；只修复测量支持的瓶颈。

1. 使用 A1 相同机器/配置/样本，分离冷启动、热启动、导入、批量写入、列表切换和长时间使用。
2. 统计 Rust＋WebView2 完整进程树，分别记录工作集、私有提交、峰值和稳定值，避免用强制清缓存或系统缓存变化冒充优化。
3. 检查 C8 的按需查询和增量保存是否真正生效；压力操作后核对数据、媒体和备份内容，速度不能以丢字段换取。
4. 重复崩溃、磁盘满和失败恢复场景，确认操作幂等和快照可用。

**验收：** 达到 A1 登记的测量/回归标准；未达到时报告瓶颈与限制，不预先承诺固定内存降幅。

### E4. 增加 Win10/11 安装与人工升级路径

**涉及位置：** 桌面 `package.json`、Tauri bundle 配置、图标/版本、安装说明；拟新增安装配置覆盖文件和制品检查。

1. 保留 `npm run build` 的无安装器 EXE，新增独立 NSIS 构建入口；以普通用户安装为优先，npm/Cargo/Tauri 版本一致。
2. 普通安装与真正离线安装分别配置 WebView2 部署，并在缺运行时的干净系统实际验证；嵌入 bootstrapper 不能当作离线安装包。参考 [Tauri Windows 安装说明](https://v2.tauri.app/distribute/windows-installer/)。
3. 固定应用身份和数据位置，验证原型 EXE → 安装版、旧安装版 → 新安装版；数据库升级执行 C4 快照门槛。
4. 卸载默认保留用户数据；重复安装、安装目录改变、中文用户名/路径、非管理员、磁盘空间不足有明确结果。
5. 记录 Win10/Win11 具体版本、x64、WebView2 下限及实测范围；缺环境不标记支持。自动更新仍不加入。
6. 提供本地候选制品、版本/哈希和安装验收记录；签名状态明确标注，证书、发布地址及上传授权在实际发行时处理。

**验收：** 新装、离线安装、覆盖升级、失败恢复和卸载保留均通过；构建安装包不等于已经发布。

## 9. 检查命令和证据要求

以下为各阶段按范围选择的命令，实际已执行项以阶段验证记录为准。开发过程中先跑最小相关测试，阶段出口再执行适用检查；通过后不无依据重复全量运行。

仓库根目录，相关 Web 行为改动时：

```powershell
node --test test/web-webdav/request.test.cjs
node test/web-ai-practice/runner.cjs
```

A4 已落地的共享测试入口：

```powershell
node --test test/dual-platform/*.test.cjs
```

`apps/desktop`，桌面代码/配置和共享资源影响桌面时：

```powershell
npm test
npm run typecheck
npm run lint
npm run prepare:web
```

`apps/desktop/src-tauri`，Rust/Cargo 变更时，在前端资源已准备后：

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test
```

`apps/desktop`，Tauri/生成/依赖/构建变更后；先构建成功，再执行运行检查，性能任务才追加 benchmark：

```powershell
npm run build
npm run test:desktop
npm run bench:desktop
```

安装包命令由 E4 新增并写入实际 `package.json` 后执行，当前 `npm run build` 不产生安装器。新增 Cargo feature 时补充真实使用组合；最终 Windows 验收覆盖分发制品。

Android 仅在实际修改原生解析、业务、Web 壳或共享构建配置时执行根规范对应 Gradle/外部解析回归。本计划通过格式 fixture 证明互通，不宣称已经测试所有 Android 运行行为。

每份阶段报告至少包含：源码/制品标识、环境确切版本、样本及步骤、预期/实际、自动或人工结果、失败归属、保全/恢复结果和未覆盖项。故障注入仅作用于隔离资源。`--self-test`、静态文件存在和历史通过记录不替代业务验收。

## 10. 重点依赖、失败退出和范围控制

| 问题 | 处理任务 | 必须保持的约束 |
| --- | --- | --- |
| 同步调用链改成异步后假成功或旧回滚 | B2/B3/B5 | 清单逐项覆盖；等待确定结果；不覆盖后续编辑 |
| 富字段/跨端信息在启动或迁移中丢失 | A2/B2/C3/C6 | 无损存储与解析归一化分开，字段级往返验证 |
| 初次原生测试碰真实数据/凭据 | C1 | 隔离先于副作用；不确定时停止测试 |
| SQLite 与媒体无法共同事务 | C3/C4/C6 | 媒体先落地，数据库后提交；快照保全引用资源 |
| C/D 并行造成迁移漏配置或漏凭据 | C7/D2/D5 | 数据与凭据分别记录状态，完整验收后才能形成升级候选 |
| 恢复配置把旧凭据发往新端点 | C6/D1/D2 | 绑定服务/端点/账号，恢复不自动关联秘密 |
| 任务结果未知时重复写入或上传 | B3/C2/C3/D4 | 按操作 ID 或远端结果核实，不能盲目重试 |
| 旧版本直接打开新数据库 | C7/E4 | 拒绝不支持 schema，使用兼容备份或支持的快照恢复 |
| 误把局部测试当中文离线/安装通过 | E1/E4/E6 | 全流程和精确环境证据，缺失项独立报告 |

阶段失败时先保留可复现输入、旧数据及快照，再修复最小相关模块。Web 与桌面分别可构建，但桌面已经切换 SQLite 的数据不能通过重新启用 localStorage 来“回退”。性能优化、依赖替换和权限调整只在已确认设计范围内推进；新增产品功能或更大安全边界另补设计。
