# 双文件导入答案匹配拆分实施计划

2026-11-19。以本地 `main` 的 `91ce850` 为基线，在 `C:/Users/30728/.codex/worktrees/3bc4/shiroha-quiz-desktop` 的 `codex/web-dual-answers` 分支执行第三批，负责人为当前会话。[第二阶段设计](../specs/2026-11-19-web-directory-app-split.md)

## 1. 固定答案与诊断

- 对同一对题目和答案文本记录题序、逐题答案、候选质量、实际采用的模式和警告。覆盖跨题型重号、未匹配、数量不同、解析兜底、混合候选去重和原题完整性。
- 通过实际 Web 双文件控件选取自建文件，检查预览及策略报告，再确认导入并重载核对保存结果。为本地 HTML 和 WebView2 验证保留双文件入口。
- 在隔离资源用例先加入拟迁入的路径，复现桌面未登记时的漏包。

## 2. 迁移答案匹配

- 将答案表接入、完整题库答案提取、候选去重和排序、各模式匹配迁到 `apps/web/import/dual-answers.js`。复用 `text-answers.js` 的答案表和重号规则，保留原有评分权重。
- 保留应用对导入草稿的所有权。题目文件解析完成后，按答案表 → 解析区 → 完整题库兜底的原有顺序准备来源。完整解析沿用会写草稿诊断的入口，再由应用生成最终报告及预览。匹配模块只接收预备好的结果。
- 接好 HTML、嵌套资产允许列表、共享测试桥接和 lint。用桌面资源回归检查同目录未登记文件的过滤与实际脚本字节。

## 3. 验证

- 先执行业务、答案表、源码加载和资源回归，再执行 typecheck、全量 lint、Web 平台和桌面与共享单测。单测沿用前两批已确认的低并发方式覆盖原有脚本范围。
- 串行生成桌面资源和正式、隔离测试制品，用本地 WebView2 走通双文件识别、预览、保存和重载。
