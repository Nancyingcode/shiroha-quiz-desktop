## 任务与验收

1. 固定原始 `styles.css` 的字节哈希，运行现有 Web 交互测试；在隔离浏览器 profile 与固定视口下记录关键页面和控件的计算样式，作为拆分前基线。
2. 先补资源完整性回归，覆盖 HTML 的共享样式顺序、桌面覆盖表最后加载、所有片段与来源字节一致、缺失或错误引用时保全已有输出。补充真实 HTTP 子路径加载检查，并确认现有组件样式测试能复用入口中的顺序。
3. 按设计中的连续顶层区段拆为八份 CSS，保持原始字节顺序。Web 入口显式加载，桌面资源生成器验证必需文件与 HTML 引用，三个组件测试按真实顺序加载。
4. 重新测量每份样式的 Stylelint 诊断，将能追溯到原文件的历史项迁至对应文件，记录跨文件检测能力变化。更新 CSS lint 回归，确保新违规仍被拒绝。
5. 对比拼接字节与页面基线，运行项目要求的 Web 与桌面测试、typecheck、lint 和 build，并串行执行桌面测试构建与 WebView2 冒烟。记录实际覆盖与环境限制。
