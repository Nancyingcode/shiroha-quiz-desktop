# CodeBuddy 客户端正式执行接入

日期：2026-10-25。用户明确要求继续完成 Shiroha 客户端 CodeBuddy 正式执行、单题解析和追问及相关测试。本设计承接已确认的[原生隔离方案](2026-10-25-codebuddy-adapter-containment.md)与[真实连接验证](../plans/2026-10-25-codebuddy-model-compatibility.md#新版适配器的单次真实连接通过)，将已通过验证的执行链连接到现有 Harness，而不引入第二套 AI 业务或放宽原生权限。

## 产品范围

执行方式仍由 API/Harness 决定，Harness 下拉决定当前提供方。CodeBuddy 只支持 `connection_test`、`question_analysis`、`question_followup`，模型由 CodeBuddy 专属下拉框选择、默认 `deepseek-v4.1-flash`，执行上限 120 秒；连接测试输出预算 1024 token，单题/追问各 8192 token（2026-10-26 经用户确认，从初始 2048 调整）。导入和批量任务由前后端明确拒绝，无 API 回退、自动重试或后台模型调用。

单题和追问沿用现有提示词、解析器、会话上下文和人工采纳。所有消息仍须通过原生角色、数量和字节限额校验；宿主按 Task 重建固定模型、预算和消息请求，不采纳 CLI 请求里的地址、模型、工具或附加上下文。模型结果须通过原始 SSE 完成证明、CLI 正文一致性与相应业务 JSON 校验。

切换提供方保留其他提供方的配置和账户。CodeBuddy 默认仅内存登录；2026-10-28 已批准的[登录状态存储设计](./2026-10-28-codebuddy-login-storage.md)增加用户主动开启的本机记住登录、重启核验与撤销清理，未开启时关闭后仍重新登录。组件准备不自动调用模型。独立账户卡片与选中的执行器状态相互刷新，但后台登录或恢复完成不自动切换提供方。

## 账户与任务生命周期

新增内部执行租约，将同一 AuthenticatedAccount 临时移出登录状态锁，租约覆盖整个 CLI 执行直至候选提交。登录服务仅保存租约标识、账户修订、无敏感数据的过期截止和任务取消标记；网络期间不持有登录状态锁。

`harness_execute` 对 CodeBuddy 增加 `accountRevision`；与现有配置 revision 一起冻结。登录开始、取消/退出与过期使旧账户修订失效，退出/换账户立即取消在途租约。旧排队请求不能借新账户；旧候选不能在换账户后返回或写入；旧租约归还不能恢复旧会话。普通任务取消若账户仍是同一所有者，可保留有效登录。401/403 或过期清除会话。

Harness 仍只有一个活动任务，沿用取消等待、恢复屏障和失败停止。账户状态与 Harness 状态仅以固定类型聚合，不返回令牌、身份或挑战信息以外的秘密。CodeBuddy 状态返回固定模型/超时及 accountRevision，原有 Codex 配置字段保持归原提供方所有。

## 组件与进程

复用当前受控下载引擎的系统代理、逐跳目的验证、总时限、取消、完整性校验、目录/文件锁及临时文件原子安装。增加固定 CodeBuddy 清单，缓存为 `runtime/codebuddy/2.175.0/codebuddy.exe`，与 Codex 路径和准备状态独立。CodeBuddy 不接受前端程序路径或下载地址。

先核对整个官方 ZIP 的长度和 SHA-256，再保持文件句柄锁定，核对固定成员头并有界解压唯一根 `codebuddy.exe`，校验输出长度与 SHA-256后安装。其余 vendor 工具不落盘。固定版本升级必须重新核对清单和布局；不实现通用归档解包。直接声明已有锁定的 flate2 1.1.10，使用 Rust 解压后端（MIT/Apache-2.0），不新增外部进程或运行时。保存官方同版本许可证原文及明确的来源记录。

正式程序在 Tauri 初始化前识别唯一内部 worker 角色，复用既有继承管道和 AppContainer。组件准备/哈希/隔离/清理失败均拒绝执行，不退回普通进程。现有威胁模型与最低 Windows 验收缺口不因正式接线而改变。

## 验证边界

先以合成账户、独立目录、假服务和真实固定 CLI 做正反回归，覆盖账户换代、取消、过期、恢复、组件失败、协议拒收、单题草稿与追问采纳及 Codex/API 回归。native-test 不连接真实账户、读取真实题库或访问官方模型；真实服务业务验收如需新增额度，先完成代码与离线验证，再明确限定请求范围并取得授权。

## 真实验收失败后的诊断补充

用户已要求“定位问题，然后验收”。先补充正式 release EXE 作为 AppContainer worker 的合成上游验证，避免仅以 console 探针或 native-test 替代实际生产进程。指定 worker 文件只用于测试/原型 feature，不进入 Tauri IPC，生产仍固定使用当前程序。

宿主保留首次失败的固定错误码，隔离进程提供的错误码须经过静态白名单映射；前端只对已知固定码追加诊断提示。错误信息不携带响应正文、请求内容、路径、账户凭据或动态服务器消息。失败仍清理进程、释放租约，不自动重试，不放宽原始响应与业务结果的采纳条件。

上一轮诊断修复后的验收按当时授权执行一次单题解析、一次追问，每次最多 2048 输出 token，任一步失败即停；使用独立数据目录和自建题，官方登录由用户完成。

## 输出预算修正（已确认，2026-10-26）

重新验收已收到 `finish_reason=length`，单题在 2048 输出 token 上限处被截断。用户已明确选择“改为 8192 并重新验收”，仅将宿主 `question_analysis` / `question_followup` 的 `max_tokens` 改为 8192，连接测试维持 1024；总时限 120 秒、单次上游、无重试和所有完整性校验保持。8192 是单次上限，不代表实际消耗，也不保证任意题目都能完成。同步更新预算回归与说明后，最多重新验收一次解析、一次追问，失败即停。

不得以放行截断 JSON 或自动续写代替修正；在网关的具体模型和推理参数映射未证实前，不盲目透传第三方模型的关闭推理参数。先前 2048 预算的失败记录保留为历史，不计作新一轮的成功验收。

## CodeBuddy 模型选择（用户明确要求，2026-10-26）

用户在 8192 预算的单题请求触发 120 秒超时后，明确要求改用 `deepseek-v4.1-flash`，并要求 CodeBuddy 模型可以通过下拉框修改。固定官方 CodeBuddy 2.175.0 包的中国版产品配置已列出该精确 ID；实际账户可用性仍须验收。

在 CodeBuddy 账户区域增加带标签的模型下拉框，默认选择 `deepseek-v4.1-flash`，另提供 `hy4-preview`、`hy3` 和 `default`（服务端默认）。前三项均列入固定官方 2.175.0 中国版 CLI 模型列表；`default` 是中国版已有模型定义且先前真实请求已送达，保留为兼容选项，不将其等同于基础版的 `default-model`。候选项采用固定白名单，不开放自由输入、任意请求参数或模型地址。选择自动保存，保存中及失败时阻止使用旧配置执行，并提供明确重试；切换模型不触发模型请求、不退出登录、不修改 Codex 或直接 API 配置。

复用 Harness 配置和修订机制，增加独立 `codebuddyModel` 字段；旧配置缺失字段时默认使用用户指定的 Flash。受控 `select_model` 操作验证活动提供方、模型白名单、空闲状态和配置修订，持久化成功后返回新状态。执行快照冻结已保存模型，宿主、隔离 worker 和真实出站请求均使用这一模型；排队旧快照继续被修订检查拒绝。连接测试仍为 1024 token，解析与追问各 8192 token，120 秒执行截止、单次上游和无自动重试保持。

下拉选项、状态、练习面板的模型名称与实际请求保持一致。回归覆盖保存/重启/切换提供方保留、拒绝未知模型、保存失败阻断、旧快照与忙时拒绝，并以假服务验证宿主请求模型。真实验收继续使用隔离合成题，最多一次解析、一次追问，失败即停。
