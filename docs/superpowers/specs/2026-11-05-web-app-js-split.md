## 入口和状态归属

[app.js](../../../apps/web/app.js) 共 10,138 行。其应用闭包直接声明了 904 个函数。建议沿用本地经典脚本的加载方式，复用现有的 `quiz-core.js`、`text-answers.js`、`backup-core.js` 和 `training.js`。新文件名均为建议名，按下表的职责逐批落地。

- **计算和格式转换**接收题目、记录、字节或本次操作的选项，返回结果。底层模块仅依赖先加载的模块。需要当前时间、缺省分数或生成 ID 时，将取得这些值的时机保留在原调用路径。
- **页面会话**持有自己的草稿、当前轮次、请求序号、取消控制器和计时器。相关操作通过少量明确的入口协作，例如读取当前题目、提交一次保存、离开时释放资源。每个可变对象指定一个写入方。
- **应用入口**保留 `startApplication`、恢复后的重新初始化、全局导航、关闭检查和 `runMutation`。后者等待原生正文读取、记录存储修订、为 `state/practice/exam` 及桌面视图建立检查点，并在保存失败时恢复。如移动会话对象，先验证事务取得的是当前对象，旧回调仍能识别已被替换的轮次。初次加载的末尾启动调用保持唯一，恢复重入时检查事件订阅和计时器数量。

## 建议拆分顺序

| 批次 | 建议落点及首个可迁移单元 | 批次验收 |
| --- | --- | --- |
| 1　练习选题和答案计算 | 将 `parsePracticeNumberRangeV58916(raw, max)` 移入 `training.js`，作为首个完整切片。随后将多空答案归一化、去重、比较所需的纯函数归入 `quiz-core.js`。当前练习范围、进度写入和读取分数输入框仍由调用方负责。 | 输入包含重复、反向或越界题号时，返回的索引和错误文案一致。多空位置、可接受答案及简答自评通过既有回归。 |
| 2　共用 ZIP 读写 | 新增 `zip.js`，把分散在文件两端的目录读取、条目解压、路径及大小检查、CRC32 和存储式打包放在一起。DOCX、XLSX、备份和 OCR 文档导出共用这份实现。文件授权、备份内部命名和文档格式解释分别归各调用方。 | 用现有 ZIP 安全样例检查穿越、重名、链接、截断、超限和校验失败。验证正常目录条目及旧备份可读。生成包比较条目名与解压内容，允许 ZIP 时间戳按原规则生成。 |
| 3　文本解析 | 延用 `text-answers.js` 处理答案表和题号匹配；在 `text-parser.js` 中逐组归集选项、题型、题干分段和候选策略。先移动无页面依赖的规则，最后处理 `parseTextQuestions` 与导入诊断的交界。原文位置与选项元数据的 `Symbol` 各保留同一实例。 | 对比题序、题型、答案、图片归属及导入警告，覆盖重复题号、共用材料、多空、双文件答案和局部修复。以旧入口对同一输入的输出作为等价依据。 |
| 4　文档和导入预览 | 分别按真实格式提取表格行列映射、DOCX 正文与图片关系、PDF 文本提取。CSV/XLSX 共用表格规则。OCR 的 worker、页面 canvas、取消操作及清理放在同一生命周期内。导入页持有当前文件、预览、人工选择和确认写入。先完成一种格式的读取 → 预览 → 保存再迁移下一种。 | CSV/XLSX 单元格、DOCX 图片和公式、文本 PDF 及离线中文扫描 PDF 实际导入。覆盖识别中取消、失败释放和重新选择文件。 |
| 5　备份与 WebDAV | 在 `backup-core.js` 中先提取单条学习记录的双向转换，特别是 `userBlankAnswers`、零分与缺省分数的优先级。然后迁移题库引用和媒体转换。WebDAV 面板另行归集配置展示、操作状态及待恢复项，网络、凭据和写入仍通过原平台与事务入口。 | 旧 Android JSON/ZIP 导入、导出再导入，逐项核对题库、收藏、错题、学习记录、得分和图片。覆盖合并冲突、替换失败保全及 WebDAV mock。 |
| 6　AI | 先把返回模式识别、HTTP 错误分类、单题结果解析归入 `ai-results.js`，再处理导入与批量预览、练习单题、错题解析各自的会话。请求配置继续取本次操作的快照，换题、换轮、停止和账户变化后重新验证结果归属。 | 传输失败与业务结构失败遵循各自的重试规则。mock 覆盖取消、迟到、草稿保留和人工确认写入。迁移导入或批量会话之前，先补不响应取消信号的假传输用例。 |
| 7　页面和提交 | 先迁移题库列表与编辑、收藏与错题、记录复盘的渲染和绑定。题干、选项、公式与图片的共同渲染可归入 `question-view.js`。最后分别归集练习和考试页面：练习拥有暂停、自评和总提交，考试拥有截止时间与自动交卷。两者通过应用入口提交。 | 检查分页、懒加载旧响应、键盘和焦点、离开再进入。验证重复提交、保存失败后重试、考试到期、总提交自评及恢复后关闭窗口。 |
| 8　条件判断与状态流转收尾 | 结合各批实际改动复核剩余候选，并处理此前审查的桌面凭据保留/替换/清除、异步有效性判断和 Rust 组件准备状态与提示的共同条件。复杂条件采用业务名称，异步检查在原检查点重新计算，配置缺省与明确关闭按原契约区分。 | 完成候选逐项处置记录，简单且清晰的合法表达式记录保留理由。Rust 修改执行 fmt、Clippy、test 和涉及的 feature 检查，随后完成联合构建与隔离桌面验证。 |

## 加载、测试和回退边界

1. 每批先列函数的调用者、闭包读写和副作用，固定现有可观察行为。一个切片先迁移实现和所有调用者，再另一步整理其复杂判断，便于区分接线失误和语义变化。业务注释随实现迁移。
2. 新增脚本时同步更新 [Web 脚本顺序](../../../apps/web/index.html)和[桌面资源生成器](../../../apps/desktop/scripts/prepare-web.mjs)中的复制条目及必需资产。通过本地脚本装载依赖，入口最后装配。新增手写文件执行现有完整增量 lint。
3. 同批更新[共享测试桥接](../../../test/dual-platform/web-source.cjs)和[加载顺序测试](../../../test/dual-platform/source-loading.test.cjs)。核对按函数名或区段取得源码的文档、AI、WebDAV 测试，以及按源码取存储键的基准工具。测试运行迁移后的实际模块，保留原业务断言和唯一启动检查。
4. 每批先跑对应小集。新增资源后检查 Web 页面、`file://` 入口及桌面生成结果。文档批运行 `npm run test:documents`，AI 和 WebDAV 批运行各自的 mock 回归。交付时在 `apps/desktop` 执行 typecheck、lint、test、`npm run test:web-platform`、build，再串行执行 `npm run build:test` 和 `npm run test:desktop` 验证 WebView2。
5. 一批只交付一个可独立验证的业务范围，前一批的调用、资源和测试全部接通后再进入下一批。验收依据是每项规则只有一份实现、状态只有一个所有者，以及同一输入得到同一业务结果。若发现需要改变判分、备份格式、权限或事务语义，单独记录该项，进入行为变更设计流程。
