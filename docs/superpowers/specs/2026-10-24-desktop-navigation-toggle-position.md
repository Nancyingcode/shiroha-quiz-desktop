# 桌面导航开关位置调整

日期：2026-10-24

状态：用户已确认「标题右侧」示例方案，要求保留展开／收起动画、雾蓝主题及悬停提示。当前工作分支以同步后的 main `b8f7f35` 为起点。

## 已确认位置

将左下角的「收起导航／展开导航」按钮移到标题栏中 `Shiroha Quiz` 名称的紧邻右侧。

标题栏从左到右为：应用图标、应用名称、导航开关、可拖动空白区、现有窗口控制按钮。

- 开关使用约 36×36px 的点击区域和约 18px 的侧栏图标，适配现有 36px 标题栏高度。
- 图标严格对应用户选中的示例：左侧独立圆头竖线与右侧圆角矩形留出空隙，18×18px、2px 深灰蓝描边；展开与收起使用同一图形。
- 常态透明、悬停浅雾蓝、键盘聚焦时显示清晰轮廓；工具提示和可访问名称明确显示当前的展开或收起动作。
- 导航展开与收起后，开关保持在同一位置，不随正文的 220ms 动画移动。
- 首页、其他普通页面及练习／考试专注模式使用同一个入口。
- 应用图标和名称保留原位置，开关与名称间隔 8px，正文及菜单顶部无需增加一行。

## 选择理由与备选

标题栏始终可见，适合作为控制整个导航区域的固定入口，也与现有雾蓝一体背景一致。用户比较了名称之前和名称之后的示例图，选择名称之后，以保留原有品牌区位置。

侧栏顶部适合作为备选，但收起后仍需保留常驻的展开入口。侧栏边缘的按钮会随动画移动，还需要处理与正文交界的遮挡，因此不推荐作为这次的默认位置。

## 实现边界

- 在桌面样式层定位现有按钮；标题栏脚本测量名称边界，随字体尺寸变化更新按钮横向位置。保留按钮原有业务绑定、偏好保存和专注模式自动恢复逻辑。
- 图标与提示使用桌面 CSS；提示复用按钮当前的中文可访问名称，鼠标悬停及键盘聚焦时显示，不维护第二份状态。
- 不在模板预置同 ID 的第二个按钮：现有初始化遇到已有按钮会跳过事件绑定。
- 开关与窗口拖拽区域保持独立，单击或双击开关均不得拖动窗口或切换最大化。
- 保留保存期间的交互限制；按钮不能因进入标题栏的事件豁免区域而绕过保存锁定。
- 保留中文可访问名称、展开状态及键盘操作；不改变 Web／Android 的按钮位置，不新增依赖、原生权限或持久化格式。
- 只调整与本按钮有关的桌面样式、必要的桌面适配、说明和回归检查，不改造整个标题栏。

## 验收

1. 默认、最小及宽屏窗口下，按钮、应用图标、名称和窗口控件不重叠。
2. 按钮在导航展开、收起和专注模式中保持固定位置，正文动画及偏好保存保持现有行为。
3. 鼠标及键盘均可切换导航；按钮不触发窗口拖拽或最大化，标题栏空白区域的窗口操作仍正常。
4. 更新原桌面检查中「导航项必须在左下角开关上方」的假设，分别检查导航区域和标题栏开关的边界。
5. 执行桌面 test、typecheck、lint、build 和实际 WebView2 smoke；只使用隔离数据与测试窗口。
