# CodeBuddy CLI 共享登录状态设计

日期：2026-11-04。状态：**用户已确认，进入实施。** 用户补充：CLI 未登录时必须引导用户登录；其余方案已确认。P0 核对后，用户进一步明确同意“仅支持独立 CLI，继续实施”；WorkBuddy 受管加密来源提示不兼容并引导独立 CLI 登录。实施与验证见[实施计划](../plans/2026-11-04-codebuddy-cli-auth.md)。

## 1. 目标与范围

用户希望 Shiroha Quiz 使用 CodeBuddy CLI 已有的登录状态，由 CLI 管理登录、保存、刷新与退出，客户端不再提供自己的“记住登录”。

本设计替代桌面端现有的独立浏览器登录与应用专属登录存储。客户端只读经过核验的 CLI 账户凭据，执行所需会话仅存在于当前进程内存中；不再向应用凭据管理器或应用账户数据库保存新的 CodeBuddy 登录。关闭客户端不会退出 CLI，CLI 未登录时客户端不能执行 CodeBuddy 任务。

本期仍限 Windows、国内个人账户，以及现有连接测试、单题解析和追问。模型选择、输出预算、120 秒超时、单次上游请求、结果校验和人工确认语义延续现有实现。其他 Harness、直接 API、Web 与 Android 的认证保持各自现有行为。

## 3. 用户体验

CodeBuddy 账户卡片改为显示“使用 CodeBuddy CLI 登录状态”，提供“刷新登录状态”和简短的终端登录说明。CLI 未登录时必须展示明确的分步引导：打开终端、运行 `codebuddy`、选择国内站并完成浏览器登录、返回客户端点击刷新；可复制固定命令，不能只显示错误。用户完成登录后即可刷新核验。未检测到兼容的认证来源时显示相应提示，不能用模型请求探测登录。

移除客户端独立登录、授权链接、取消浏览器登录、记住登录、保存重试和退出登录入口。账户登录、切换和退出由 CLI 完成；客户端不修改 CLI 的任何认证文件，不提供可能同时注销其他使用者的共享账户退出按钮。日常任务的停止按钮继续保留。

原生来源初始化只检查本地文件；当前活动提供方为 CodeBuddy（含重启恢复的选择），或用户主动刷新时才执行账户核验，不自动切换提供方、不下载组件、不调用模型。关闭应用只释放本进程会话。CLI 更新凭据、切换账户或退出后，刷新状态和下一次任务都必须反映当前来源；执行期间的变化按第 5 节处理。

设置界面清楚区分“未登录”“正在核验”“可使用”“已过期”“认证格式不兼容”“账户类型不支持”“读取失败”和“网络核验失败”。网络失败提供重试，不显示为退出成功，也不继续使用未核验的旧会话。

## 4. 原生只读认证来源

新增内部 CLI 认证来源模块，负责定位、限长读取、来源识别和快照一致性检查；本期只读独立 CLI 普通会话，受管加密包装明确拒绝，不做解密。保持现有认证客户端和执行租约，避免另建模型执行链。

### 4.1 定位与输入边界

- 按已验证 CLI 版本的产品配置与目录规则定位唯一国内个人账户记录，明确默认根、自定义数据根及认证标识的优先级。不得把 `CODEBUDDY_CONFIG_DIR` 直接等同于认证根。
- 首期只接收原生端确定的默认认证根；前端不得传程序路径、目录、文件名、令牌、产品配置或服务地址。不接收其他认证路径覆盖；自定义产品或无法唯一定位时报告失败，不扫描整个用户目录、备份文件或历史账户。
- 不执行 PATH 中未经确认的程序，不通过 shell 拼接命令，不加载 CLI 用户设置、hooks、插件、MCP、记忆或 API Key helper。不把环境变量中的 API Key 当作个人账户登录。
- 对路径祖先及实际打开的文件验证 symlink/junction、文件类型与来源边界；拒绝网络位置和越界重解析。读取失败不复制到可写位置后重试，不扩大 ACL。
- 文件、字段、集合数量均有明确上限；P0 固定限额并用超限样例验证。禁止将完整文件或解码错误原文写入日志。

### 4.2 解码与账户核验

- 先检查退出标记，再读取稳定快照；解码与账户核验后、模型发送前和结果提交前再次确认来源未变化。退出标记存在时即使旧认证文件尚未删除，也按未登录处理。
- 只支持经过合成 fixture 验证的独立 CLI 普通会话和默认产品认证标识。JSON 解析在原生进程内完成；受管加密包装整体拒绝，不读取或导出密钥、不降低 CLI 的凭据保护设置。
- 未知版本、损坏、无法解密、到期或不支持的账户均明确失败；不回退到旧应用凭据、其他产品账户、历史 `.info` 备份或任意服务地址。
- 将必要的 access token、账户标识、国内域名及绝对有效期转为内存会话，再通过现有官方账户端点核验实际个人账户绑定。不得仅相信本地账户类型或把相对有效期从读取时刻重新计算。
- refresh token 不交给模型执行器，不用于客户端自行刷新，也不写回 CLI。过期时重新读取来源；CLI 尚未刷新或重新登录时提示用户在 CLI 处理。
- 真实令牌不进入 WebView、Tauri 返回值、命令行、临时文件、应用数据库、备份、恢复点或日志。认证快照指纹只在内存中使用，不记录可用于关联账户的原始字段。

### 4.3 P0 通过条件

先用 CLI `2.179.3` 的内嵌实现和官方发行材料核对产品标识、路径优先级、退出标记及受保护字段格式；用假账户和隔离目录构造正反 fixture，证明只读适配能够恢复正确身份且完全不写 CLI 数据。应用固定执行组件 `2.175.0` 保持隔离，单独验证宿主取得的合法内存会话仍可走现有受控链。

P0 核对发现，`2.179.3` 的 standalone 路由不进行凭据保护 bootstrap；WorkBuddy 受管路由则需要宿主通过专用 socket 提供保护能力。原设计“受保护格式无法读取则不启用”的门槛因此先暂停启用，用户随后明确批准本期收窄为独立 CLI。实施仅支持已核对的 standalone 普通会话，受管加密包装整体拒绝，不能把缺失令牌视为可用账户；不读取密钥、不关闭保护、不回退其他来源。自定义产品、受管保护环境及未经验证的账户路径明确不兼容，普通配置目录覆盖不改变已核对的认证路径。

P0 不调用真实收费模型；是否需要新增生产依赖、专门凭据桥接进程或升级固定 CLI，均须先说明理由、维护和许可影响，再更新设计。

## 5. 状态、并发与执行隔离

客户端可缓存已核验的内存会话以供当前任务使用，但不能把缓存当作共享登录的最终来源。继续保留配置 revision、accountRevision、取消标记与独占执行租约。

1. 选中 CodeBuddy 后刷新认证来源；账户核验成功且来源快照仍一致时才标记可使用。普通状态查询读取当前快照，不在每次 UI 轮询中重复联网。
2. 每次新任务取得租约前重新检查本地来源；来源变化立即撤销旧会话、递增 accountRevision，并阻止旧排队请求。新来源重新核验后，只能接受用户随后发起的新任务，不自动重发旧题目。
3. 执行期间用有界本地监测检查认证文件和退出标记，建议检查间隔为 1 秒；发送真实模型请求前和采纳结果前必须同步检查。监测读取失败也撤销当前租约，禁止无期限继续使用缓存。
4. 发现 CLI 退出、换账户、凭据变化或过期时取消在途任务，丢弃迟到结果；已经送达服务端的请求仍可能消耗用量，取消不承诺撤回。相同账户令牌轮换同样保守取消，避免无法区分退出后重登的情况。
5. 首期只保证在检查点与监测间隔内观察到变化，不声称磁盘变更与远端请求绝对原子。监测线程归登录服务所有，关闭、账户失效或停止监测时释放，不能在 UI 反复挂载后累积。
6. 普通任务取消不修改 CLI 登录。题库恢复仍取消任务、作废现有内存租约并关闭 CodeBuddy 的使用；本进程内需要用户显式刷新才重新接入。下一次启动可从 CLI 重新核验，界面说明恢复不会注销外部 CLI 账户。

沿用现有无互联网 AppContainer、单次上游预算、固定模型路径白名单、临时 worker 授权和原始 SSE/CLI 正文证明。执行工作进程不得读取真实用户 HOME 或认证目录，不将真实令牌塞入 CLI 环境变量；认证来源适配只发生在原生宿主。任何来源读取、核验或隔离失败均阻止任务。

## 6. IPC 与前端改动

继续使用主窗口、本地来源限制下的 `codebuddy_control`。新界面只需固定的状态查询、带当前 revision 的主动刷新动作；取消任务继续走现有 Harness 控制。精确动作、错误码、phase 联合类型和原生返回结构在实施计划中固定并同步契约样例。

状态可包含来源枚举 `cli`、phase、revision、busy、固定中文消息及旧存储清理状态；不返回凭据、uid、昵称、认证文件路径或 CLI 原始输出。移除旧独立登录与 remember 动作的可达业务入口，非法或旧动作明确拒绝，不静默触发共享账户操作。前端继续使用 generation、请求序号和账户 revision 丢弃迟到响应，并保留键盘操作与 aria-live 状态。

## 7. 现有应用凭据的过渡

新版本不再保存或自动恢复应用专属 CodeBuddy 登录；共享模式唯一认证来源为 CLI。不把旧令牌写入 CLI，不用旧应用登录覆盖 CLI 当前账户，也不把“客户端此前已登录”等同于“CLI 已登录”。

旧应用存储暂时只保留撤销与清理兼容路径。首次成功核验兼容的 CLI 账户后，先永久撤销旧应用记录，再按既有命名空间清理对应 Windows 凭据分片；失败保留可重试清理记录，不得恢复为可执行来源。CLI 暂未就绪时不提前物理删除旧凭据，但仍不使用它们执行；提示用户先完成 CLI 登录。此流程不要求两个来源账户相同，因为不会迁移任何账户数据或令牌。

清理范围只限当前应用数据根登记的 CodeBuddy 记录，不枚举删除其他系统凭据，不删除 API/WebDAV/Codex 凭据，不操作 CLI 文件。题库恢复、导出和备份不携带新的认证信息。降级版本能否再次使用尚未撤销的旧记录须在升级说明中说明；完成永久撤销后，旧版本也不能恢复这些记录。

## 8. 改动范围与验收

预计涉及认证来源新模块、现有 auth/login/store 的过渡接线、Harness 修订与恢复屏障、原生初始化和命令契约、桌面账户卡片、共享类型及相关测试。桌面资源仍从 `apps/web` 生成；不手改 dist，不新增通用文件、凭据、HTTP 或进程 IPC。

用户确认设计后，先在 `docs/superpowers/plans/` 编写中文实施计划，再按红—绿—重构推进。不得把本设计的待核验部分或已有登录存储的批准状态当作新方案已经实现、已经通过真实账户验收。

必须覆盖：

- 默认及支持的自定义来源；已登录、未登录、过期、错误账户类型、未知格式、损坏、无法解密、超限、退出标记优先和读取时来源变更。
- 登录前后、退出、同账户令牌更新、换账户、文件删除、文件替换、读取失败、网络核验失败及重启；任何分支均无新应用凭据写入、无 CLI 文件改写。
- 任务前核验、执行中变更取消、迟到核验/模型结果拒绝、旧租约归还、恢复屏障和普通停止；配置切换不能修改其他提供方账户。
- 旧存储永久撤销、分片删除失败重试与进程中断；失败不丢失题库，也不复活旧应用会话。
- symlink/junction、恶意路径、异常字段、错误域名、日志脱敏，以及保留 AppContainer 与受控出口的负向回归。
- 全部自动化用假凭据、mock 服务和隔离 profile；native-test 不读取本机 CLI 真实账户。真实账户验收另行记录范围，模型用量需明确授权，不能把框架或假服务通过当作真实兼容已验证。
