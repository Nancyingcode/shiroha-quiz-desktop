# 刷题提交模式设计

状态：用户已确认，按此方案实施。

后续修订：用户要求总提交后直接显示错题一览与作答对照，并修复答题时不可用的 AI 解析。本次按该明确要求调整原先的 AI 禁用规则，复用现有解析与记录数据，不改变判题或持久化格式。

## 目标与范围

在开始刷题前选择“单题提交”或“总提交”。本次修改 Web 与复用 Web 的桌面端；Android 原生界面不在本次范围。沿用现有题目判定、错题维护和练习记录，不新增依赖或持久化格式。

## 现有实现

设置入口位于 `apps/web/index.html`。`apps/web/app.js` 的 `startPractice` 创建本轮状态，`renderPracticeQuestion` 渲染题目，`submitPractice` 处理单题提交；`recordPracticeAnswer` 更新统计、错题与明细，`finishPractice` 保存记录。简答题目前通过参考答案与人工自评完成判定。

## 交互与行为

1. 练习设置增加“提交方式”，默认单题提交；开始后本轮模式固定，再练一次沿用当前设置。不增加跨重启保存偏好。
2. 单题提交维持现有行为：逐题提交后显示答案和解析，简答题人工自评；仍可主动查看答案。
3. 总提交中，各题选择或输入仅为本轮内存草稿；上一题、下一题、题号跳转和重新渲染均保留草稿，提交前可修改。导航与统计区分已填写、未填写，不显示正确率和对错。
4. 总提交前不提供单题提交或看答案；两种模式均允许答题时主动打开 AI 解析与追问，不自动请求服务。AI 可包含参考答案，但不自动填写、判题或计入成绩。收藏可用，题目编辑在本轮总提交结束前禁用，避免判定依据变化。未配置 AI 时可以前往设置，保留本轮草稿，返回后继续作答。
5. 总提交按钮在答题中始终可用，末题不直接结束练习。点击后显示已填写及未填写数量；存在未填写题时明确提示这些题将按错误计入本轮，取消则继续答题。
6. 确认总提交后锁定草稿，客观题复用现有判定；未填写题计为错误。已填写的简答题进入逐题人工自评，显示本人作答和参考答案，全部自评后完成记录与汇总。结果页直接列出本轮全部错题，显示原题序、来源题库、完整题干、你的答案、正确答案及已有解析；选择题包含选项字母与内容，多空逐空对照，未答显示“未作答”，全对显示无错题提示。使用本轮保存的明细快照，保持记录页入口不变。
7. 总提交及简答题自评过程防止重复判题、重复累计和重复保存。保存失败保留本轮状态并允许重试，成功后才清理本轮。
8. 总提交前退出时提示草稿尚未提交，可取消退出或明确放弃；不把草稿写为已判题记录。确认总提交后须完成自评和保存再退出，不静默丢失待自评答案。
9. 错题、收藏等快捷练习入口先进入练习设置，保留题目来源或单题范围，选择提交方式后开始，避免绕过模式选择。
10. 顺序练习进度只在正式完成判定后推进，草稿填写不代表已完成。

## 实现约束

复用现有练习状态与题目复合键，分离草稿、提交锁定、待自评和完成状态；模式仅保存在本轮状态。沿用现有受控存储接口，不修改 Rust、IPC、数据库或备份格式。新增控件提供中文标签与键盘入口，确认提示和异步失败提供可访问反馈。

## 验收

- 两种模式均可在开始前选择；默认单题模式无行为回归。
- 单选、多选、判断、填空、多空与简答题草稿跨跳转保留；分组内同 ID 题目不会串答案。
- 总提交前不自动揭示答案或判题；AI 只按用户操作生成，切题和设置往返不丢草稿，保存 AI 解析不触发简答自评或提前判题。提交后草稿不可更改。
- 总提交结果页完整显示错题及本人/正确答案，无错题时提供明确反馈；不改变已保存记录。
- 未答题确认可取消；简答题逐题自评正确累计；重复点击与保存失败重试不重复记录。
- 退出、再练一次、快捷入口、顺序进度与键盘操作符合上述语义。
- 实施时先补行为回归，再修改代码；运行相关 Web 回归、桌面测试、typecheck、lint、构建和隔离 WebView2 验证，分别报告覆盖范围与环境缺口。
