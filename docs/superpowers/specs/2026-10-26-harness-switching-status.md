# Harness 组件复用、下载中切换与启动状态设计

日期：2026-10-26。状态：用户已明确确认，按本设计实施。

## 1. 目标与现状

本设计覆盖 Codex 与界面现有的 CodeBuddy；用户所称 workbuddy 在本轮按当前 CodeBuddy 入口理解，不新增或更名提供方。保留已有独立卡片和模型标签间距。

代码核对结果：

- `harness_runtime.rs` 已分别存放两种组件，并在完整校验缓存成功后直接复用；尚未通过真实请求观测证实“每次切换重新下载”。当前在校验缓存前就上报下载总字节，界面统一显示“组件准备中”，容易混淆本地校验与下载。
- `harness.js` 的提供方下拉框及切换函数都阻止准备中切换；原生 `SelectAdapter` 同样要求全局空闲。仅解除下拉框禁用不足以支持切换。
- 组件准备与执行共用 active 操作及配置 revision；切换会改变 revision，现有完成处理会把旧 revision 的结果判为过期。
- `codebuddy-login.js` 首次查询前使用 `signed_out` 和 revision -1，虽然正文显示读取提示，状态标签仍显示“尚未登录”。Codex 初始状态同样没有明确的读取状态。

## 2. 用户可见行为

### 2.1 已安装组件保留并复用

- 切换提供方不删除组件、不退出账户、不清除各自模型选择，也不重置已确认的组件状态。
- 本次运行中已校验且文件未变的组件直接显示“组件已就绪 · 使用本地组件”；反复切换不重新启动准备任务。
- 启动或需重新核验时显示“正在检查本地组件…”，不展示下载百分比或下载字节。继续保留原生完整性校验，不因优化速度放宽安全边界。
- 只有缓存缺失、损坏或版本不匹配时下载当前审核版本；界面明确说明原因。下载失败或取消不得清除已有完整缓存。
- 下载、校验、解压、就绪分开显示。仅下载阶段展示网络传输量；总量未知时只显示已下载大小，不编造百分比。

### 2.2 下载时可切换

- 下载期间 Harness 下拉框可用。切换保存成功后显示目标提供方卡片，原组件任务继续在后台进行。
- 组件任务归属于提供方与任务标识，不归属于当前选中的卡片；旧任务完成不得把选择切回去或覆盖另一提供方的模型、账户和错误。
- 每个提供方最多一个准备任务；最多一个网络下载，另一组件需要下载时排队。已有本地组件的检查与使用不等待其他提供方下载。
- 卡片外只在存在后台组件任务时显示一条摘要，例如“Codex 正在后台下载 · 42%”，提供“查看”和“取消下载”；查看切到对应卡片。
- 切回下载中的提供方展示同一任务进度，不从零开始；切回已准备完成的提供方立即显示本地就绪。
- 取消只影响所指提供方的组件任务；排队任务可取消。取消、失败后必须主动重试，不因切换反复自动重启。
- 切换持久化失败时保留原生已确认的选择并显示可重试错误；下载继续，不丢失任务引用。
- 本轮只解除组件准备及只读状态查询对切换的阻塞；模型请求、登录授权流程、退出清理、恢复和配置写入保留现有必要互斥。
- 已就绪且已登录的目标提供方可以执行，不被另一提供方的后台组件下载阻塞。关闭应用结束在途下载，保留完整组件；本轮不增加断点续传或跨启动自动恢复下载。

### 2.3 启动与刷新登录状态

- 设置加载阶段显示“正在读取 AI 设置…”，尚未拿到配置前不猜测默认提供方。
- 配置返回后可切换提供方；每张卡片分别显示组件状态和账户状态。
- 账户首次读取时标签显示“读取中”，正文显示“正在读取登录状态…”，设置 `aria-busy` 并保留状态区域高度，避免按钮跳动。
- 读取期间登录、退出和模型执行暂不可用；模型选择仍遵循现有保存与配置互斥规则。组件下载和提供方选择不因只读账户查询被禁用。
- 查询成功才显示“已登录”或“未登录”。CodeBuddy 仍仅在进程内保留登录，重启查询完成后显示真实的未登录状态，不虚构持久会话。
- 查询失败或等待超过 15 秒，显示“暂时无法读取登录状态”及“重新读取”；不当作已退出，也不删除凭据。超时失效的迟到回复不得覆盖后续重试。
- 手动刷新显示“正在刷新登录状态…”。已知结果可作为上次结果展示，但确认前不能重新启用执行。
- 账户提示只在账户区域展示一次；执行区只承载任务结果、失败或执行条件，不复制同一条账户告警。
- 加载反馈同时包含文字；减少动画偏好下使用静态标记。异步结果使用礼貌播报，不播报每个下载字节变化。

## 3. 实现边界

- 在现有原生 Harness 服务中分离按提供方持有的组件任务和模型/授权任务，不引入通用任务框架。
- 准备任务以 adapter、版本及独立 operation/generation 标识验收结果；提供方选择 revision 的变化不作废合法组件下载。恢复、关闭及显式取消仍必须使相关任务失效。
- 组件完成只提交所属提供方的组件结果；尤其 Codex 准备完成不能回写旧配置快照并覆盖新选中的 adapter。
- 扩展受控业务状态查询以返回各提供方组件阶段与后台任务摘要；定向取消参数限定为已有提供方及任务标识。保持本地来源和主窗口权限、固定下载来源、逐跳校验、哈希、原子安装及安全缓存目录边界。
- 前端分别管理配置读取、账户读取、组件准备与模型执行的状态；避免单一 busy 禁用所有控件。账户已读与授权有效必须分别判断，不能用加载结束代替已登录。
- 查询只观察状态；需要准备时由既有设置入口启动。保留首次进入设置自动准备组件的语义，不因启动读取状态主动调用模型或弹出授权页面。
- 受影响文件预计为 Harness 原生服务与组件准备、共享状态契约、桌面 Harness/CodeBuddy 账户界面及对应测试。Rust 修改前另读项目 Rust 指南。

## 4. 验收

1. 两种组件已缓存：连续往返切换，各自路径与校验状态保留，网络下载请求计数为零。
2. 启动时缓存有效：本地检查后就绪，不出现下载百分比、不发起组件下载。
3. 缺失或损坏缓存：仅对应组件进入下载；失败保留既有完整文件，不误判就绪。
4. Codex 下载期间切到 CodeBuddy：选择保存成功，原进度继续；切回仍为同一任务。后台完成不能改变当前选择。
5. 两个组件缺失：下载串行排队，无重复任务；定向取消不会取消另一提供方任务或删掉完整缓存。
6. 就绪目标提供方不被其他提供方下载阻塞；执行中仍不能非法切换。恢复、关闭和迟到结果不会越过失效屏障。
7. 延迟首次账户响应：两张卡片均显示读取中，无“尚未登录”闪现；失败/超时可重试，旧响应不覆盖新状态。
8. CodeBuddy 重启后正确显示未登录；Codex 真实查询结果与缓存组件状态互不混淆；不会为了查询账户调用模型。
9. 以隔离 mock 验证请求计数、并发与取消；补 WebView2 切换、加载、键盘和减少动画验证，不使用真实账户、题库或收费 API。
