当前开发与发行构建都通过 Tauri hook 执行 `prepare:web`。脚本先校验输入与路径，再删除整个 `dist`、复制资源、执行桌面 HTML 转换及 bridge 打包。Web 源目录实测包含 369 个文件，共 94,255,909 字节；这不是过滤后的实际复制量，也不是耗时测量结果。

## 方案

### 内容一致时不写入

保持 `prepareWeb(sourceDir, projectDir)` 入口与现有命令不变。先完成现有输入、安全与 HTML 转换校验及 bridge 打包，再形成预期输出清单；清单包含现有筛选规则保留的 Web 资源和桌面生成文件。

逐文件比较目标与预期内容，仅在内容不同或目标缺失时写入。普通资源可先比较大小，大小相同时再比较内容；不能仅凭大小或时间戳判定相同。生成文件直接比较最终字节，不先复制 Web 原始 `index.html` 再覆盖。

未变文件保留原有时间戳。初始阶段不引入持久化缓存清单，也不缓存 esbuild 结果，避免增加缓存失效规则和依赖变动遗漏。文件比较内存按单个文件控制，不同时载入全部离线资源。

### 清除失效资源

取消每次删除整个 `dist`，改为删除预期清单之外的生成文件与空目录。处理源文件删除、可选 `data`/`media` 消失和文件与目录类型互换，确保增量结果与全新生成一致，不能留下旧业务脚本。

任何删除操作仍只发生在已校验的固定 `dist` 内。保留源与项目重叠检查、源与输出树的符号链接/junction 拒绝、frontend 输入校验及离线必需资源校验；已有输出即便无需更新也必须接受安全校验。不能因复用输出跳过这些检查。

输入校验或转换失败时，保留原输出。写入期间发生 I/O 错误应明确失败，后续运行重新比较并修复；不声称整个目录更新具备事务原子性。资源准备和读取 `dist` 的构建仍串行运行。

### 保持构建产物语义

继续包含 PDF、OCR、MathJax、字体、许可证等资源；保留现有 CSP、原生权限、开发来源与测试隔离。不修改 Rust 优化级别、release 特性、NSIS 压缩策略或安装包格式，不新增生产依赖。

首轮重点是重复构建与少量前端修改。Rust 首次依赖编译、首次运行时下载及安装包压缩可能仍占主要耗时；若实测需要改变这些策略，另行给出有数据支持的方案。

## 测试与验收

先新增回归测试，再实现增量逻辑：

1. 连续生成两次，所有未变输出内容和时间戳保持不变；测试使用预设旧时间戳，避免文件系统时间精度造成假通过。
2. 修改单个文件，仅对应输出更新；覆盖相同长度及保留源时间戳的内容变化。
3. 源文件删除、可选目录删除、目标多余文件和文件/目录互换后，输出与全新生成一致。
4. 输出缺失或内容被篡改时重新生成正确字节；不信任目标时间戳。
5. 保留现有路径重叠、链接、缺失离线资源、非法 HTML 与失败保全测试，增加增量复用路径的边界覆盖。

实施前按项目规则核实相关进程再安装依赖。使用相同机器、资源与串行负载，比较旧实现和新实现的首次准备、无变化准备、单文件变化准备耗时，重复测量并记录中位数。测量修改仅使用隔离 fixture 或可恢复的临时副本，不更改真实题库。

完成后运行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`；再串行执行 `npm run test:dev`、`npm run build:test` 和 `npm run test:desktop`，验证开发启动及生成资源的实际 WebView2 行为。记录首次与重复 build 的耗时及编译日志，区分资源准备、Rust 编译和运行测试，不把资源准备提速比例当作整体打包提速比例。

安装包构建若受运行时下载或工具环境限制，应单独报告；没有测量的数据不宣称提速。不提交、不推送、不发布。
