# 答题清空选项设计

日期：2026-10-29。状态：用户已批准并授权实施；执行记录见[实施计划](../plans/2026-10-29-answer-options-clear.md)。

## 1. 目标与现状

作答时提供明确的“清空选项”入口，让用户将本题恢复为未作答后重新选择。

已核对[共享答题代码](../../../apps/web/app.js)、[样式](../../../apps/web/styles.css)、[浏览器回归](../../../test/dual-platform/browser-page.cjs)和[刷题提交模式设计](2026-10-24-practice-submit-modes.md)：

- 单题练习和总提交练习已通过 `bindOptionSelect` 支持再次点击已选的单选、判断选项取消选择；多选可逐项取消。已有回归覆盖鼠标、空格、数字键及切题保留空草稿。
- 练习页没有明显的一键清空入口。单题练习使用 `practice.answerState` 保存本轮作答；总提交另有填写统计与提交锁定。
- 模拟考试使用独立的选项事件和 `exam.answers`，目前没有相同的单选取消处理，也没有一键清空。考试答题卡依赖答案状态计算已答数量。

本方案以增加明确入口、统一作答体验为目标，沿用现有草稿与提交流程。

## 2. 覆盖范围

| 范围 | 设计 |
| --- | --- |
| Web 与桌面的单题练习 | 提交或主动看答案前可清空本题选项 |
| Web 与桌面的总提交练习 | 确认总提交、锁定答案前可清空任意题目的选项 |
| Web 与桌面的模拟考试 | 交卷前每道选择题均可单独清空 |
| 单选、多选、判断 | 有可作答选项时提供清空入口 |
| 填空、多空、简答 | 保持现有文本编辑方式，不增加清空文本功能 |
| 错题本、收藏、记录、题库预览与结果页 | 只读展示不增加清空入口；从这些页面开始练习后遵循对应练习规则 |

本期不包含 Android 原生界面或历史 Web assets 同步，与现有 Web/桌面练习功能的维护范围一致。

## 3. 推荐交互

### 3.1 明确的一键入口

在选项列表上方增加轻量工具行，左侧为“选项”，右侧为“清空选项”次要按钮。练习和考试位置一致，不放入收藏、编辑题目等题目管理操作中。

```text
题干……

选项                         [清空选项]
○ A. 第一项
● B. 第二项
○ C. 第三项
○ D. 第四项

[上一题] [下一题] [提交答案] [看答案]
```

- 使用现有次要按钮风格，不采用删除操作的红色样式。窄屏允许工具行换行，不遮挡题目或选项。
- 当前题没有选择时，按钮保持可见但禁用；有选择且允许修改时启用。
- 点击后一次清空本题全部勾选，多选不必逐项取消。保持当前题、阅读位置和其他题目的答案。
- 不弹确认框，不增加撤销流程；用户可直接重新选择。
- 清空成功后在本题显示简短反馈“已清空本题选项”，通过状态区域供辅助技术读取。
- 已提交、已看答案或总提交已锁定时，作答界面的按钮禁用；沿用已有反馈说明当前状态。进入只读结果页后不展示此按钮。

### 3.2 保留便捷取消

保留练习页现有“再次点击已选单选或判断选项即可取消”的操作，并将相同语义补齐到模拟考试。点击另一项仍为正常切换，多选仍按项切换。

两种入口最终得到相同的本题答案状态；通过再次点击取消最后一项后，“清空选项”同样变为禁用。

不新增全局快捷键。按钮使用原生 `button`，支持 Tab 到达、Enter/Space 激活；保留练习页现有数字键操作。鼠标点击选项文字、圆框和键盘操作应得到一致结果。

## 4. 状态与提交规则

清空只修改本轮、本题的答案草稿，不能解释为撤销已经提交的答题记录。

| 场景 | 清空后的行为 |
| --- | --- |
| 单题练习，尚未提交也未看答案 | 本题 `chosen` 为空，选中高亮清除；不累计已刷、正确、错误，也不推进顺序进度。此时提交仍提示先作答 |
| 总提交练习，尚未锁定 | 本题草稿为空，答题卡变为未填写，已填写数量减一、未填写数量加一；最终提交沿用既有未填写提醒及判定规则 |
| 模拟考试，尚未交卷 | 本题答案为空，答题卡变为未答，已答数和进度同步减少；计时继续，最终交卷沿用既有未作答处理 |
| 单题已经提交或主动看答案 | 不允许清空，不修改已记录作答、对错或反馈 |
| 总提交确认中、已锁定、自评中或保存失败待重试 | 不允许清空；取消提交确认后恢复可编辑，确认锁定后保持既有自评与保存流程 |
| 考试交卷或保存过程中、交卷完成后 | 不允许清空，不得改动评分所用答案；保存失败后的可操作状态遵循现有事务回滚流程 |

补充约束：

- 单题练习仍按“正式判题完成”标记答题卡；清空未提交草稿不新增已填写统计。
- 勾选、高亮和内存草稿必须同步清除，不能仅改 DOM。切题、题号跳转、收藏重绘、返回练习后不得恢复旧选择。
- 使用现有题库 ID 与题目 ID 复合键定位；考试中的按钮必须限定所属题目容器，不能误清同卷其他题目或另一题库的同 ID 题目。
- 清空本身不调用保存、判题、错题维护或完成练习逻辑，不修改题库标准答案、历史错选、收藏、AI 解析或追问记录，也不自动发起 AI 请求。后续主动 AI 请求读取当时的最新草稿。
- 总提交确认期间临时禁止清空，避免确认框中的填写数量与随后锁定的答案不同。普通保存事务忙碌时也禁止清空。
- 考试到时自动交卷与清空均先检查当前会话及提交状态，以先完成的状态转换为准；交卷取得答案后，迟到事件不得再修改答案，也不暂停或重置计时。
- 不增加跨重启草稿恢复，不新增数据库字段、IPC、原生权限、存储格式或依赖。

## 5. 实现与无障碍边界

主要调整共享 Web 的作答渲染、选项事件和局部样式，复用 `collectAnswer`、`applyAnswerStateV26`、现有草稿更新及答题卡刷新入口。集中复用本题清空与选项同步逻辑，不重构无关答题业务，不复制第二份桌面实现。

只在可作答界面接入按钮，避免共享 `questionHtml` 的只读调用方出现清空入口。事件执行前重新判断本题是否仍属于当前会话、是否允许修改；按钮禁用状态与事件守卫采用相同业务条件。

按钮提供包含题号的可访问名称，例如“清空第 3 题选项”。激活后将焦点移至本题第一个可用选项，避免清空按钮变为禁用后丢失键盘位置；不触发重新选中，不滚动到页首。状态反馈使用文字，不仅依赖颜色。无需新增动画或覆盖层。

桌面资源仍由 `apps/web` 生成，不手改 `apps/desktop/dist`。

## 6. 验收与后续实施

用户批准设计后再编写实施计划，并先添加可复现的行为回归，再实现功能：

1. 单题、总提交、考试分别覆盖单选、多选、判断：初始禁用、选择后可用、一键清空、清空后重新选择。
2. 再次点击已选项取消，以及鼠标点击文字/输入框、空格、练习数字键的现有行为均保持正确；取消最后一项等价于清空。
3. 清空后切题、题号跳转、收藏重绘仍为空；总提交填写统计和考试已答进度准确，不出现残留高亮或旧草稿。
4. 清空只影响本题，跨库同 ID、多题同屏和多选部分已选均隔离；文本题、只读题目不出现按钮。
5. 单题空答案提交仍被阻止；总提交取消确认后草稿仍为空，确认后按未填写处理；考试交卷及到时交卷使用清空后的答案。
6. 已提交、已看答案、提交确认中、总提交锁定与保存期间不能清空；快速连击、迟到事件及保存失败重试不改变已锁定答案或重复生成记录。
7. 清空不写入记录、错题或题库，不改历史错选，不发起网络请求；之后主动使用 AI 读取空草稿。
8. 键盘可操作且焦点合理；窄屏、长选项、图片选项与桌面 WebView2 的按钮位置、状态反馈通过验证。

实现阶段执行相关 Web 浏览器回归和单题 AI/提交模式回归，桌面执行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`，再通过 `npm run build:test` 与 `npm run test:desktop` 验证隔离 WebView2。分别报告实际覆盖与环境缺口。

设计阶段仅运行文档检查，确认 UTF-8、代码围栏、本地链接和差异；不以设计检查通过代表功能已实现或运行验收通过。
