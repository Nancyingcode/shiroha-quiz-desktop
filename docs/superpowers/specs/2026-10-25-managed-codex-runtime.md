# Codex 运行组件自动管理

日期：2026-10-25。用户已明确批准：程序自动准备和管理 Codex，用户只需登录订阅；手动选择程序放入高级设置；继续保留其他 Harness 的扩展接口。

## 目标与范围

沿用[AI Harness 设计](2026-10-24-ai-harness-execution.md)中的订阅认证、任务执行、取消、凭据隔离与业务结果确认边界。本轮不更换认证协议，不加入 API Key，不开发学习助手，也不实现其他 Harness。

默认体验为进入 AI 设置并选择 Harness/Codex，程序自动准备受管组件，然后点击订阅登录即可自动保存所需执行配置并启动官方登录。模型测试仍由用户主动触发。高级设置保留手动选择、检测、路径和版本，并提供恢复自动管理。旧配置中的非空路径迁移为自定义来源，不静默替换。

## 组件交付与校验

首次明确进入 Harness 设置或点击登录时，原生层按需取得固定的官方 Windows x64 Codex 0.163.0，存放在应用 `ai-execution` 下的独立组件目录。复用现有 reqwest、sha2 与文件能力，无新增生产库。直接下载官方 EXE，避免新增解压器；文件大小为 341270320 字节，SHA-256 为 `2692c8c7bb2cf8b0aefe638741fc90236f4b824c59578ce84994f9de58200993`。

固定来源为 `https://github.com/openai/codex/releases/download/rust-v0.163.0/codex-x86_64-pc-windows-msvc.exe`。只允许 HTTPS、固定 GitHub 主机及发行资源重定向主机，逐跳校验、限制跳数、超时和总字节数。不携带题目、用户凭据、授权头或 Cookie。校验缓存后复用，不查询 latest、不后台静默升级；未来升级仍需新的协议与工具边界验收。

下载写入随机临时文件，只有大小和完整哈希正确才原子切换到正式文件；失败或取消清理本次临时文件，保留原有文件及授权。拒绝路径链接/junction，使用本地准备锁防止跨进程同时安装。每次执行继续使用原有带文件锁的固定哈希校验，下载完成不等于允许放宽工具或进程权限。保留官方 LICENSE、NOTICE 和来源记录。现有离线 NSIS 指 WebView2 离线安装；Codex 首次准备仍需联网，缓存后准备不再联网。

## 2026-10-25 系统代理修复

用户反馈开启系统代理后组件下载失败，并明确要求区分有代理与无代理的网络环境。组件下载显式读取当前 Windows 用户的手动系统代理：开启时按目标协议和绕过规则选择代理，关闭或未配置时直连；每次主动准备/重试重新读取，已经开始的下载使用该次配置快照。启动器的 `HTTP_PROXY` 等环境变量不覆盖 Windows 系统开关。代理连接失败不会悄悄改为直连。

复用现有 `windows-sys` 的 WinHTTP 配置读取能力和 reqwest 的显式代理接口，不新增 crate、通用网络 IPC 或代理地址持久化。统一地址、分协议地址及本地/域名绕过规则使用隔离测试覆盖。PAC/WPAD 自动发现不属于本次静态代理修复；检测到只有 PAC 脚本而无静态代理时明确提示，避免把未解析的代理配置当作直连。此前 Codex CLI 的认证、受限执行和凭据隔离不改动。

下载仍限于固定官方 HTTPS 来源并逐跳验证目标；保留证书、大小和哈希校验、取消与总时限。错误只返回固定文案，不记录代理地址、代理凭据或重定向签名参数。

## 状态与 IPC

复用 `harness_control`，不新增通用下载或进程接口。新增 `prepare_runtime`（准备当前选择）和 `use_managed_runtime`（显式切回受管组件）控制；调用方不能指定下载 URL、目标路径或校验摘要。状态增加 `runtimeSource`（managed/custom）、`runtimeState`（unprepared/preparing/ready/failed/cancelled）及下载字节进度。准备期间复用唯一活动任务与取消屏障，状态查询不启动认证进程；结果仅在原修订仍有效且未取消时生效。

准备不切换 API/Harness 模式，不发起模型请求。自动准备每次进入设置仅触发一次，失败或取消要求显式重试；初始化和普通界面刷新不重启下载。登录串行等待准备、保存 Harness 配置、启动授权；取消、失败、模式切换或恢复发生后，后续登录不能继续。自定义来源仅校验用户选定的程序，不自动替换。

## 扩展与验收

共享业务仍使用 Harness 任务接口，组件管理属于 Codex 适配器内部；新增适配器沿用状态、准备、认证、执行、取消的边界，不把 Codex 下载逻辑写入题目业务。

自动化仅使用假二进制、小型字节流、假凭据及隔离目录，覆盖缓存复用、哈希/大小错误、重定向拒绝、取消/重试、并发、旧路径迁移、登录次序、恢复屏障和 API 配置保留。生产组件真实性用既有已核验官方文件验证，无真实模型调用。完成适用 Node、类型、lint、Rust、构建与 WebView2 门禁后，重新打开新版供用户登录。
