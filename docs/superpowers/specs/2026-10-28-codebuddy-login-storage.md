# CodeBuddy 登录状态存储设计

日期：2026-10-28。状态：**用户已批准整体设计，进入实施。** 用户已明确选择“默认不勾选，由用户主动开启记住登录”。实施与验证见[实施计划](../plans/2026-10-28-codebuddy-login-storage.md)。

本文承接[CodeBuddy 客户端正式执行设计](./2026-10-25-codebuddy-client-execution.md)与[原生隔离设计](./2026-10-25-codebuddy-adapter-containment.md)，规划 Windows 桌面端跨进程保存和恢复个人账户登录。既有文档中的“仅内存登录”仍描述当前实现，本文批准并实施后再更新相关现行说明。

## 1. 目标和范围

用户主动开启“在此设备记住登录”后，在令牌仍有效且账户核验通过的情况下，重启应用可继续使用 CodeBuddy。默认保持当前体验：凭据只在当前进程内，关闭应用后重新登录。

本期覆盖保存、重启恢复、关闭记住登录、退出、令牌失效、写入中断与清理失败。仅支持当前的单个国内个人账户；切换 Harness 提供方保留账户，恢复账户不自动选择 CodeBuddy、不下载组件、不调用模型。

本期不保存 refresh token，不实现自动续期、多账户切换、跨设备同步、浏览器/官方 CLI 凭据导入。当前代码没有令牌刷新契约，不能把“记住登录”承诺为永久免登录。过期或服务端拒绝授权后仍需重新登录；后续自动续期需要独立核对协议与设计。

## 3. 推荐存储结构

### 3.1 分层与选型

| 数据 | 保存位置 | 生命周期 |
| --- | --- | --- |
| access token 分片、uid、domain、有效期及完整性信息 | Windows 凭据管理器，CodeBuddy 专属命名空间 | 用户开启记住后写入；关闭记住、退出或确认失效时撤销并清理 |
| 命名空间 ID、活动记录 ID、存储代次、待清理记录 | 原生私有 `codebuddy-account.sqlite3` | 与当前应用数据根绑定；不含令牌、uid、昵称或完整登录链接 |
| Client、Session、单调时钟截止、账户 revision、租约、challenge | Rust 进程内存 | 每次启动重建；challenge 不跨进程恢复 |
| 账户状态、保存结果和固定错误提示 | 前端临时视图 | 从受控 IPC 获取；不写 localStorage、IndexedDB 或共享配置 |

推荐复用现有 `Provider` 的 Windows 凭据读写能力，新增 CodeBuddy 专属内部存储模块，不改造 API/WebDAV 的业务接口。私有 sidecar 延续现有项目模式，不修改题库 schema，也不增加生产依赖。

其他方案：单条凭据无法覆盖现有令牌上限；明文配置文件不满足凭据边界；DPAPI 加密文件可作为另一套设计，但需要新增加密、文件落盘和删除生命周期。本期优先统一到项目已有的 Windows 凭据管理器。

系统凭据保护沿用项目既有威胁模型，不承诺抵御已经可以以同一用户执行任意原生代码或读取应用内存的程序。

### 3.2 凭据记录

每次成功保存生成新的随机 `recordId`，凭据目标由宿主按固定规则构造：应用标识、development/release、随机 `namespaceId`、CodeBuddy、recordId 和固定分片序号。目标名不使用 uid、昵称、外部路径或前端输入；测试使用独立 namespace。

一组记录包含：

- 1 条 manifest：`schemaVersion`、`recordId`、`uid`、`domain`、`expiresAtMs`、`savedAtMs`、`chunkCount`、`tokenBytes`、`tokenSha256`。manifest 序列化后也必须检查 2560 字节上限；不保存昵称、challenge、刷新令牌或整个厂商响应。
- 1 至 8 条 token 分片：每片最多 2048 字节，合计最多沿用当前 16 KiB 上限。当前令牌只允许可打印 ASCII，可按字节切片并通过现有字符串 Provider 存取。
- 重组时验证格式版本、记录 ID、片数、顺序、单片及总长度、令牌字符约束和摘要。摘要用于发现拼接或部分写入错误，不作为身份认证；账户仍必须由固定服务核验。

manifest 和分片都属于秘密，不实现面向日志的 `Debug`，不进入 IPC、CLI 参数、环境、worker 管道、题库、导出包、恢复点或 WebDAV 备份。只有持有它们的原生宿主可以发起固定认证请求。

### 3.3 私有元数据与隔离

`codebuddy-account.sqlite3` 仅记录版本、随机 namespace、递增的存储代次、活动 recordId 及待提交/待清理记录。跨进程保存意图由已提交的活动记录表达，不重复保存布尔字段。待写记录在调用系统凭据 API 前登记，保证进程中断后可以准确清理孤立分片。

默认新建记录的保存意图为 false。只有已提交的活动记录可参与恢复，不能通过枚举凭据名称“寻找最近一次登录”。数据库缺失、损坏、未知版本或活动记录不完整都不得从零散凭据猜测恢复身份；保留可诊断的固定错误和已知清理线索，不自动覆盖损坏文件。

增加当前数据根专属的 `codebuddy-account.lock`，由登录存储服务持有至进程结束。同一数据根第二个实例无法取得锁时，只使 CodeBuddy 账户功能不可用，不复用另一个进程的会话、不阻断题库使用。沿用路径祖先检查，覆盖数据库、WAL/SHM、锁与撤销标记，拒绝 symlink/junction 越界。

development、release、native-test 的元数据和凭据命名空间均隔离。namespace 是隔离标识，不是秘密；不同工作树不得因同一 Windows 用户而访问生产账户。正常版本升级保持应用标识和数据根时可读取受支持的记录版本；不支持的版本安全拒绝，不自动降级重写。

## 4. 状态与用户操作

账户是否可用与是否保存是两个独立事实。新增账户 phase `restoring`，保留现有 `signed_out/authenticating/signed_in/expired/failed/cancelled`；保存结果另用 `persistenceState` 表达，避免把“保存失败”显示成“登录失败”。

建议 `persistenceState` 为 `none/saving/saved/clearing/cleanup_required/error`，另返回当前 `rememberLogin` 意图及白名单 `persistenceErrorCode`。字段只用于界面，不授权执行；可执行状态仍由原生检查会话、revision、租约和清理屏障。

| 事件 | 账户与存储行为 | 界面结果 |
| --- | --- | --- |
| 默认登录，未勾选 | 完成个人身份核验，只生成内存会话 | “已登录，仅本次使用” |
| 勾选后登录 | 核验成功后保存；保存未结束前不接受执行租约 | 成功后“已登录，已在此设备记住” |
| 保存失败 | 可保留本次内存会话；撤销未提交记录并登记清理 | “已登录，但未能保存，下次启动需重新登录”；清理不确定时仍阻断执行 |
| 已登录时开启记住 | 仅空闲时接受；不要求重新登录，将当前有效会话保存 | 按实际结果显示保存状态，可重试 |
| 已登录时关闭记住 | 先持久撤销，再删除保存记录；保留当前内存会话 | 清理完成后“仅本次使用” |
| 重启且存在完整已保存记录 | 自动进入 restoring，核验账户后才发布会话 | “正在恢复登录”；成功后显示已登录 |
| 恢复遇到断网、超时、5xx | 保留未被明确判失效的存储记录，不启用账户 | “暂时无法核验已保存的登录”，可重试恢复或退出清理 |
| 本地到期、明确 401/403、身份不匹配 | 撤销保存记录，取消租约并清理内存 | “登录已过期，请重新登录”或固定身份核验失败提示 |
| 退出登录 | 立即阻断执行与迟到结果，持久撤销并清理全部相关记录 | 只有确认后显示“已退出登录”；失败保留“重试退出” |
| 取消交互登录 | 取消 challenge 与当前登录尝试，清理该尝试的待写记录 | 不保存未完成授权 |
| 取消恢复 | 只取消本次恢复，不删除已保存记录；仍阻断执行 | 可重试恢复，或通过退出清理；下次启动可再次恢复 |
| 切换提供方、普通模型任务取消、关闭应用 | 不等同于退出登录；保存记录按用户选择保留 | 不改写其他提供方配置 |

“记住登录”初始不勾选，登录进行中冻结本次选择；已经保存的会话重启后显示已勾选。成功关闭记住或退出后恢复为未勾选。开启/关闭记住在模型任务占用租约期间禁用并由原生拒绝；退出始终可发起，并取消在途工作。

保存失败后的重试必须由用户操作触发；不会无限后台写入。状态轮询只读取快照，不触发网络核验或再次保存。网络恢复失败后也不后台反复请求。

## 5. 保存、撤销与崩溃恢复

### 5.1 保存提交顺序

1. 冻结当前账户 revision 与存储代次，确认会话有效、用户选择记住、没有执行租约。
2. 事务登记待写 recordId 与固定分片数，写入 manifest 和分片，再完整读回验证。系统凭据调用放入阻塞工作线程，不能持有登录状态锁等待 IO。
3. 以串行存储协调器和代次比较保证提交顺序；再次检查账户 revision、撤销状态、有效期和记住意图。检查及活动记录提交必须相互协调，不能在检查后被退出请求插入而仍然发布旧记录。
4. 提交活动 recordId；将旧记录转入待清理集合，随后逐条删除。完整提交并确认必要清理后才报告 `saved`。
5. 任一步失败，未提交记录不可恢复，已知分片进入补偿清理。原本已有有效保存记录时，替换失败不静默丢弃它；用户明确关闭记住或退出则以撤销为准。

进程在分片写入或读回期间结束：下次只清理 pending，不恢复它。进程在活动记录提交之后结束：只核验新活动记录，旧记录只用于清理。因故未取得提交确认时，界面不得宣称保存成功。

### 5.2 撤销顺序

退出、关闭记住、确认过期或身份失效共用原生撤销入口，但分别决定是否保留当前内存会话。

1. 内存立即设置屏障、递增账户 revision，取消登录/恢复和不再合法的租约。旧成功、旧状态响应、旧租约归还都不能改变当前账户。
2. 事务递增存储代次，清除活动引用并登记清理项。逻辑撤销先于系统删除，删除失败也不能让重启恢复旧账户。
3. 删除 manifest 与全部已登记分片，确认不存在后移除清理项。删除不存在的目标视为幂等成功；只删除本 namespace 内由应用登记的目标。
4. 系统删除失败进入 `cleanup_required`，保留撤销记录，提供明确重试入口；新登录、保存和执行保持阻断，避免叠加新的账户所有权。

数据库无法写入时，复用现有服务层思路，尝试写入并同步当前数据根的专属撤销标记；启动必须先处理该标记，再考虑恢复活动记录。若数据库和撤销标记都无法持久化，只能保证当前进程已阻断，必须提示“退出尚未完成，请重试”，不能承诺重启后也已经退出。

存储工作串行处理，但不会让慢 IO 阻止内存取消。已开始的迟到写入可结束，随后必须按原代次登记并清理，不能提交为活动账户。不能只在调用系统 API 前检查一次 revision。

## 6. 重启恢复与认证边界

启动时异步检查元数据、撤销标记和未完成补偿；不阻塞题库初始化。若有完整活动记录，读取凭据并验证版本、长度、分片摘要及有效期，进入 `restoring`。

恢复需要在认证模块内部创建新 `Client` 和新 owner UUID，再由经过验证的持久化字段重建 Session。不能序列化并复用旧 owner、`Instant`、请求客户端、取消标记或租约；不能通过删除现有 owner 校验来兼容恢复。

有效期只保存原始绝对截止 `expiresAtMs`，不得每次启动重新套用原始 `expiresIn` 延长有效期。根据当前时间计算剩余时长并使用受检运算重建单调时钟截止；系统时间无效或早于 `savedAtMs` 时拒绝自动恢复。跨进程无法完整证明时钟未回拨，仍必须进行服务端核验，不把本地时钟检查当作服务端授权。

每次自动恢复只调用一次固定 `GET https://copilot.tencent.com/v2/plugin/accounts`，验证保存的 uid 在返回列表中有唯一匹配、属于 personal、没有企业身份且 `pluginEnabled=true`。沿用固定 origin/path、证书校验、禁止重定向、代理、超时和响应限长。保存的 domain 只可作为已校验的授权上下文头，不能决定目的地址。`/login/account` 依赖旧 challenge，不用于重启恢复。

这次请求仅携带账户授权所需信息，不包含题目、答案或学习记录，也不请求模型。勾选项旁说明“下次启动会联网核验登录状态，不会自动调用模型”。这是新增的启动认证请求；当前源码已使用 accounts 端点，但跨进程恢复的真实兼容性仍须单独验收，不能从 mock 通过推定真实可用。

服务端明确拒绝或身份不匹配时撤销。临时网络失败、5xx、无法确定身份的协议异常阻断恢复，保留记录供显式重试，不静默删除或切换到另一账户。发布新会话前再次检查 revision、代次与取消；恢复超时或退出后的响应不得恢复登录。

当前退出为本应用本机撤销，不表示退出官方浏览器会话或远程吊销所有设备令牌。本期没有已核对的远程注销端点，不新增猜测的请求。

## 7. 受控 IPC 与界面

继续使用现有 `codebuddy_control` 与主窗口/本地来源校验，不新增通用凭据、文件或 HTTP 命令。

| 动作 | 建议输入 | 约束 |
| --- | --- | --- |
| status | `{kind:"status"}` | 只读快照；不读取任意记录、不联网 |
| login | `{kind:"login",revision,remember:false}` | 新前端显式发送布尔值；兼容缺失字段时只按 false 处理，绝不沿用 true |
| set_remember | `{kind:"set_remember",revision,remember}` | 只接受显式布尔值；已登录且空闲时保存或清除，可用同一动作重试 |
| retry_restore | `{kind:"retry_restore",revision}` | 仅有已保存记录且恢复可重试时接受；一次请求，无模型调用 |
| open_login / cancel / logout | 保留现有固定动作 | logout 在恢复和清理失败状态也可用；cancel 支持交互登录与恢复 |

原生继续拒绝未知字段、URL、路径、recordId、uid 和 token。新增状态字段由前后端同步维护类型与校验；`rememberLogin` 表达意图，`persistenceState` 表达结果，不能只靠一个勾选框声称已保存。

`signed_in` 仅由原生认证结果产生。保存/清理屏障同步到 Harness 的 busy/ready 判断；`restoring` 期间不能借出会话或提交旧候选。页面继续使用 generation、请求序号和 revision，状态重绘不得清除退出失败屏障。

新增语义化复选框和“重试恢复”按钮，使用现有 `aria-live` 提示保存失败、恢复进度及清理结果。Web 端继续隐藏账户卡片。提示不显示 uid、昵称、令牌、动态服务端消息或本地路径。

## 8. 迁移、备份与恢复

- 旧版本没有本应用持久化的 CodeBuddy 会话，无需扫描其他程序的配置，也不迁移浏览器或官方 CLI 登录。升级后默认不记住，用户下一次主动开启即可。
- `codebuddy-account.sqlite3`、锁、撤销标记及凭据记录不进入题库备份、恢复点或 WebDAV 包。题库回滚不能回滚账户撤销代次或复活旧记录；实现时逐条核对现有恢复入口。
- 若某个现有操作具有“清除账户/恢复屏障”的语义，CodeBuddy 必须接入同一业务屏障；不得因存储另设模块而绕过。普通题库导入/导出不改变账户选择。
- 元数据损坏时不删除真实题库、不重新创建并假装干净；仅阻断受影响的账户功能。丢失元数据后不自动枚举和认领系统中的零散凭据，已知记录才可定向清理。
- 保留数据的应用升级继续保留记住状态。卸载后是否保留数据沿用当前安装策略；需要清除此设备登录时先执行应用内退出。本期不擅自修改安装器或声称卸载会清空系统凭据。

## 9. 实施拆分与验收

整体设计已批准，按[实施计划](../plans/2026-10-28-codebuddy-login-storage.md)及红—绿—重构流程推进。实施分为以下五部分；设计批准不包含提交或推送授权：

1. **存储层**：新增 CodeBuddy store，复用 Provider，完成分片、元数据、独占锁、保存事务、撤销及补偿。先覆盖边界和故障注入。
2. **认证恢复**：增加仅供原生调用的会话导出/重建入口和 accounts 核验；覆盖 owner、有效期、身份匹配与取消。
3. **登录状态机与 Harness**：接入保存选择、恢复、撤销屏障、租约和 revision；所有旧登录/旧保存/旧恢复竞态先有失败回归。
4. **界面与契约**：复选框、保存结果、恢复重试、清理重试，更新受影响的共享类型、前端及页面测试。
5. **隔离桌面验证与说明**：更新资源生成结果的源入口、桌面验收脚本和现行文档；不手改 dist。

主要改动预计涉及 `harness_codebuddy_auth.rs`、`harness_codebuddy_login.rs`、新增 `harness_codebuddy_store.rs`、`main.rs`/`lib.rs`、Harness 状态接线、`frontend/codebuddy-login.js`、`apps/web/index.html` 及相关测试。通用 Provider 若需增强限长或测试故障注入，单独覆盖 API/WebDAV 回归，不修改其凭据契约。

| 验收组 | 必须覆盖 |
| --- | --- |
| 默认与选择 | 未勾选始终不写系统凭据；重启未登录；主动勾选才保存；缺失 remember 不等于 true；关闭记住后当前会话仍可用 |
| 容量与格式 | 2048/2049 字节、16 KiB、超限令牌；manifest 超限；缺片、错序、摘要不符、未知版本均拒绝恢复 |
| 保存事务 | 每一分片写入失败、读回失败、提交失败、提交前后崩溃；pending 不被恢复，旧活动记录按既定规则保全 |
| 退出与失效 | 退出后重启不恢复；删除失败与撤销标记生效；系统/JSON 401、403、本地过期、身份不匹配；全部写入失败时不声称跨重启清理成功 |
| 并发 | 保存中退出、恢复中退出、取消后旧授权完成、旧租约归还、旧写入晚到、重复操作、跨进程锁、切换提供方；均不能复活旧账户 |
| 恢复 | 有效账户恢复；重新绑定 owner；不续算 expiresIn；时钟回拨、断网、超时、5xx、畸形响应；每次恢复最多一次账户核验、零模型调用 |
| 数据隔离 | development/release/test 不互读；题库和所有备份无秘密；普通题库回滚不复活凭据；元数据损坏不影响题库修复 |
| 界面 | 保存失败与登录失败分开；实际保存成功才显示已记住；恢复/清理期间阻断任务；键盘、标签和 aria-live；Web 卡片仍隐藏 |

自动测试使用合成身份、FakeProvider 和隔离目录。现有 FakeProvider 仅在进程内，不能直接证明跨进程恢复：为 native-test 增加只允许写入隔离测试根的合成持久 Provider，生产构建不得启用该路径。另用随机 namespace 和假令牌验证真实 Windows 凭据读写、分片与删除，不读取生产记录；报告不包含任何凭据内容。

文档检查在 `apps/desktop` 执行 `npm run lint:docs`，对脚本未覆盖的设计和计划补同等 UTF-8、代码围栏、本地链接和差异检查。

实现检查：桌面 `npm test`、`npm run typecheck`、`npm run lint`；Rust `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`，补默认/native-test 所影响组合；按需先 `npm run prepare:web`。完成 `npm run build` 后，再以 `npm run build:test` 生成隔离程序并运行 `npm run test:desktop`，覆盖真实 WebView2 重启流程。共享 Web 与单题 AI 行为按实际改动追加已有回归。

## 10. 已确认的整体决策

已确认：**默认不勾选记住登录，由用户主动开启。**

用户已批准采用：Windows 凭据管理器的有界分片 + 无秘密的私有事务记录；重启自动核验后恢复；退出先撤销再清理；首期保留当前令牌过期后重新登录的规则。实现进度、模拟测试与实际验收范围以[实施记录](../plans/2026-10-28-codebuddy-login-storage.md)为准，不能将设计批准当作真实账户验收通过。
