# Harness 单一提供方选择

## 授权与目标

用户明确要求按“执行方式 → Harness → Codex / CodeBuddy / DeepSeek”的层级展示对应订阅界面，当前 AI 以下拉选择为主，切换保留其他提供方的登录状态。本设计落实该明确交互要求，不继续真实账户或模型测试。

## 行为

- 直接 API 模式只显示 API 配置。Harness 模式显示提供方下拉框和唯一对应面板。
- Codex 保留现有组件、模型、订阅与运行设置；CodeBuddy 使用现有账户登录面板；DeepSeek 显示尚未接入的订阅说明，不伪造登录或模型能力。
- 提供方选择立即保存为唯一活动 Harness。选择写入期间或失败时禁止旧提供方执行；不得静默回退 Codex。任务或 Codex 原生设置操作忙碌时禁止切换。
- 选择只改变活动提供方与执行模式，不注销、清理或覆盖各账户登录。CodeBuddy 会话仍只在当前进程内保留；Codex 保留现有独立订阅凭据。切换并不增加重启后的登录持久化能力。
- CodeBuddy 与 DeepSeek 当前均不可执行模型。选中它们后显示对应原因；测试、导入解析和单题请求均不得调用 Codex。
- 既有 API / Harness 模式的显式保存交互保留；提供方下拉发生变更时自动选用 Harness 并保存。退出或清理仅作用于当前面板明确指向的账户。

## 实现边界

复用 Harness 配置已有的 `adapter` 字段，允许固定三种值，旧配置仍默认 Codex。增加受控 `select_adapter {adapter, revision}` 操作：校验修订与空闲状态，只更新活动选择、模式和修订号，保留 Codex 组件与模型配置。原生状态返回真实选项；所有 Codex 专属操作及执行入口检查活动提供方，非 Codex 不触发组件准备、订阅检测或任务执行。

界面由 Harness 控制器统一决定面板显隐，CodeBuddy 控制器仅更新自己面板内部状态，隐藏不会注销会话。共享业务标签按冻结配置的 adapter 显示。前端在选择保存期间及草稿不一致时禁止执行，原生再次校验，旧任务快照不能越过切换后的修订。

## 验收

覆盖 API 与三种 Harness 的面板互斥、切换前后 Codex 授权与 CodeBuddy 会话保留、选择保存/重启恢复、选择失败与迟到结果、非 Codex 拒绝执行且无 Codex 调用。使用合成身份与隔离测试资料，不发真实模型请求。
