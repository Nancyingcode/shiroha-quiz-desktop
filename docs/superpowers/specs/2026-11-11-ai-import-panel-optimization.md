# 全项目 JavaScript 优化专项：AI 导入面板

2026-11-11 · 已随全项目规划确认实施。本专项覆盖 Web 与 Windows 桌面共用的 AI 辅助整理、AI 核对和 AI 补解析。基于本地 `main` 的 `49a2007`，参考附件 `ai-import-panel-optimization-plan.md` 和 `ai-panel-event-binding-optimization.md`，已按当前源码重新定位。跨模块的批次顺序及其余脚本见[全项目 JavaScript 优化规划与逐文件清单](2026-11-11-project-javascript-optimization.md)。

## 1. 优先保护用户刚改过的题目

**P0.1 · AI 整理不得覆盖后续识别或编辑。** 普通识别和表格识别会取消批量预览任务，但正在等待的 AI 整理仍可持有原请求。用真实会话模块和模拟传输挂起请求，将预览从 A 换成 B 后，旧请求成功会用 AI 结果替换 B，失败会把预览恢复成 A。已有取消后重启测试覆盖了请求所有者变化，这里发生变化的是同一请求等待期间的草稿。[识别入口](../../../apps/web/app.js) · [请求与回滚](../../../apps/web/ai-import-sessions.js) · [草稿快照](../../../apps/web/import-preview.js)

- 先为普通识别、导入表格替换草稿和原位编辑各写回归。用延迟响应覆盖首次成功、首次失败、进入文本清洗兜底前，以及兜底已发出后再修改的情形。
- 建议复用现有取消和请求所有者检查。在替换或修改草稿的业务入口让旧整理失效，回写结果、发起兜底、恢复快照前核实仍有权修改这份草稿。核对原文/选区、整份预览及原位编辑，发送给模型的截取摘要不足以判定整份草稿相同。
- 验收时对比新题目、选中项、诊断、提示和实际发送次数。旧任务不得提交结果、恢复旧快照或触发额外兜底，当前任务仍可结束并释放忙碌状态。草稿未变且结构化结果确实不可用时，原有一次文本清洗兜底仍可完成；本地解析失败只需撤回本次解析写入的临时诊断等状态。

**P0.2 · 批次按用户最初选中的题目发送。** AI 核对与补解析在开始时保存数组索引，每批发送前才按索引取题。用 A 至 E 五道模拟题选中 B、D，设每批 1 题，首批挂起时删除 A，实际发出的两批是 B、E。现有的逐批指纹校验在取出 E 后才建立，无法发现 E 原本不在目标中。[批量循环](../../../apps/web/ai-import-sessions.js) · [预览删除与编辑](../../../apps/web/question-editor.js)

- 建议在点击开始时确定有序目标题目的身份、内容指纹。每批发送和回写前按这个集合核对。原题仅移动且仍能唯一识别时继续处理；目标题已删除、内容已改或无法确定身份时停止后续批次，提示重新选择，保留此前仍适用的建议。
- 验收覆盖删除无关题后依旧发送 B、D，以及删除或修改 D 后不发送第二题。加入相同题干的不同 ID、无稳定 ID、重排、取消重启和迟到响应。核对 mock 实际收到的题目和最终建议归属。模型省略 ID 时可按序号匹配已发送批次；回到实时草稿，应重新确认题目身份。覆盖“采纳”和“编辑后使用”两条路径。[结果匹配](../../../apps/web/ai-results.js) · [题目标识与回退](../../../apps/web/app.js) · [建议采纳](../../../apps/web/ai-import-panel.js)

## 2. 统一开始条件和单批题数

| 顺序 | 当前行为 | 方案与验收 |
| --- | --- | --- |
| P1.1 · 双面板互斥 | 请求层两个开始入口已在首个异步等待前互查运行状态。工具栏也检查两种任务，面板里的开始按钮各只检查自己的任务。 | 为导入和预览复用同一个“两种任务任一正在运行”判断。两个面板均打开时，覆盖四种运行状态、连续点击、取消和结束后恢复。各自的输入要求、运行提示、取消按钮继续独立生效。 |
| P1.2 · 批量输入 | 普通刷新将空值或 0 回写为模式默认值。界面和请求层各自读取并限制数值，小数仍能进入批次循环。 | 建议采用 1～30 的整数。打开或显式重置时核对模式默认 20、补解析默认 10。编辑中保留输入；空值及非法值显示原因，预计次数显示“—”，按钮禁用，直接调用也发出 0 个请求。两层共用同一校验逻辑，开始时固定本次有效批量。 |

用 31 道目标题、每批 30 题验收，界面应预计 2 批，mock 应依次收到 30 题和 1 题。两种模式分别覆盖清空后重输、1、30、0、负数、小数、31 和非有限值；总目标 200 题可开始，201 题提示缩小范围。上述预计次数按业务批次计。[面板](../../../apps/web/ai-import-panel.js) · [执行入口](../../../apps/web/ai-import-sessions.js) · [输入控件](../../../apps/web/index.html)

继续按任务能力和就绪状态决定入口显示、禁用、重试与“前往 AI 设置”。检查完成只刷新状态，保留焦点、无障碍提示和用户主动发起模型调用的语义。传给桌面 Harness 的 `aiTasksBusyV99` 还包括练习、复盘、连接测试等来源，继续用于原有的平台判断。[启动就绪设计](2026-11-11-ai-startup-readiness.md) · [装配与忙碌查询](../../../apps/web/app.js)

## 3. 减少目标诊断和面板刷新

**P2.1 · 目标范围按需诊断。** 用真实面板工厂、模拟 DOM 和 500 道合成题，在每次调用 `collectAiPreviewTargetDetailsV992` 时单独统计注入的题目状态查询。核对与补解析共 108 组合法组合的基础索引和最终索引已与独立预期对照。实施时以相同输入重跑，分别断言数组内容、顺序、范围错误和调用次数。[目标收集](../../../apps/web/ai-import-panel.js) · [题目诊断](../../../apps/web/text-parser.js)

| 范围与筛选 | 当前每次诊断调用 | 验收目标 |
| --- | ---: | ---: |
| 自定义题号、已选择、全部题目 | 各 500 | 0 |
| 当前筛选结果，显示全部 | 1,000 | 0 |
| 当前筛选结果，异常题、正常题或异常优先 | 各 1,000 | 各至多 500 |
| 核对模式，仅异常题 | 500 | 至多 500 |

先根据范围决定是否需要题目状态，再处理补解析条件。保持原始索引、去重、已选升序、异常优先且同组按原序、空白解析及去空白后 19/20 字的分界。此计数只覆盖目标选择；构建实际请求时使用的逐题诊断仍有用途。先在面板内整理计算，等行为稳定后再依据复用需求决定是否提取纯函数。

**P2.2 · 合并重复刷新，保留必要的状态更新。** 在两个面板均可见、Harness 桩仅保存回调时，单次绑定初始化中导入/预览分别刷新 1/2 次；一次 Harness 通知为 2/2 次。同模式连续两次普通预览刷新会重写两次范围选项。[面板同步与选项](../../../apps/web/ai-import-panel.js) · [全局渲染与文本输入](../../../apps/web/app.js) · [会话结束及取消](../../../apps/web/ai-import-sessions.js)

- 以一次绑定同步或一次 Harness 通知为单位，每个可见面板最多刷新一次。检查 `renderAll` 和请求取消/结束处的连续调用；保留题目编辑器单独调用预览同步的能力。同一文本输入事件先清理旧选区，再显示最新范围。
- 隐藏的导入面板仍须在选中文本失效时回到“全部”；重新打开后验证发送范围。Harness 变化也须更新连接标记、练习和复盘。普通刷新保留任务结果提示，主动修改范围、条件或批量继续清除旧提示。
- 在当前选择框首次渲染、模式变化或选择框节点被替换时构建范围选项。同一模式下普通刷新写入选项 0 次。核对 → 补解析 → 核对分别验证可选范围；显式重置回到自定义题号、起点 1、终点为 20 与题数的较小值、解析条件为“仅无解析题目”及对应默认批量。

## 4. 单独整理六个固定按钮

**P3 · 保留直接绑定，集中选择器到处理器的映射。** 六个按钮位于 `bindAiImportEventsV99`。页面通过原生 `document.querySelector` 查找节点，处理器在绑定时均已就绪。真实面板加模拟节点已验证重复绑定后每个按钮单击仍只执行一次，移除一个可选节点后其余按钮可用。这一项的收益是便于核对映射。[面板事件](../../../apps/web/ai-import-panel.js) · [设置处理器](../../../apps/web/ai-settings.js)

| 按钮 ID | 当前处理器 |
| --- | --- |
| `ai-test-connection-v99` | `testAiConnectionV99` |
| `ai-toggle-diagnostics-v375` | `toggleAiDiagnosticV375` |
| `ai-copy-diagnostics-v375` | `copyAiDiagnosticV375` |
| `ai-copy-ollama-cors-v375` | `copyAiOllamaCorsCommandV375` |
| `ai-clear-settings-v99` | `clearAiSettingsV99` |
| `ai-organize-import-btn-v99` | `openAiImportPanelV99` |

采用面板内的小函数统一查询和可选节点判断，继续把原处理器直接赋给 `onclick`。切换和复制诊断的选择器使用复数 `diagnostics`，对应处理器使用单数 `Diagnostic`。验收逐一核对业务动作、缺少可选节点、重复初始化、关闭重开及异步按钮反馈。页面复用同一个控制器；文本框已有绑定标记，桌面 Harness 重新绑定时替换回调。待实际需要在同一 DOM 上更换控制器时，再设计接管或解绑。[桌面绑定](../../../apps/desktop/frontend/harness.js)

## 5. 实施顺序与验证入口

1. 设计确认后，在 `docs/superpowers/plans/` 写入中文实施计划，从当时的本地 `main` 核对基线并绑定任务分支。建议由同一负责人依次处理 P0.1、P0.2、P1、P2、P3；这些任务共用面板、草稿和会话。每个行为切片先补能复现问题的回归，再实施并复测。局部变量遮蔽已有独立分支 `codex/web-ai-panel-no-shadow`（`12881bd`），规划时尚未合入基线。复用该项成果时须保留主线的就绪检查与重试路径。
2. 对 P0/P1 先扩展请求会话测试，使用可控的延迟、成功、失败和取消，断言实际题目载荷。P1～P3 在 `test/dual-platform/` 补面板级状态、调用计数和点击映射覆盖。保持现有全局工厂、返回的 14 个方法和 `mode()`、DOM 标识、题目 ID、建议人工确认和存储边界。[请求用例](../../../test/dual-platform/ai-import-retry.test.cjs) · [应用装配](../../../apps/web/app.js)
3. 浏览器通过项目内的模拟 AI 服务验证普通识别与迟到响应、跨批删除、清空后重输、双面板互斥、就绪失败后重试，以及建议经人工采纳并确认导入才写入题库。复用已有页面场景。[浏览器用例](../../../test/dual-platform/browser-page.cjs)
4. 实施交付时，在 `apps/desktop` 运行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run test:web-platform`。共享资源在 Windows 桌面再运行 `npm run build`、`npm run build:test`、`npm run test:desktop`，按相同输入在隔离 WebView2 中补测 smoke 未覆盖的交互。页面和桌面分别记录实际结果。[项目脚本](../../../apps/desktop/package.json) · [双端验证说明](../../../test/dual-platform/README.md)

规划阶段的两项 P0 复现和调用计数均来自 Node 隔离验证。当前文档工作树未安装桌面依赖；在同提交且测试源码一致的本地主工作树，现有 AI 导入重试、Harness 和 CodeBuddy 执行三份测试共 154 项通过。新增场景的浏览器与 WebView2 验收留待实施。
