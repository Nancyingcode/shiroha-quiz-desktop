# Shiroha Quiz Web 与 Windows 桌面双端设计

日期：2026-10-23

状态：双端方案已获用户明确确认；本文件是据此整理的实施基线，功能完成状态以代码和验收结果为准。

确认依据：用户要求“就按这个双端方案实施，保留 Web 端，桌面先支持 Win10/11，重新写一份设计文档”。既有方向授权持续有效，实施前不重复确认相同选择。本文取代[关联会话中的改造路线草稿](thread://01a16496-3d95-7723-9a2d-178595ccf5a7?hostId=local)；[原型设计](./2026-10-23-tauri-prototype.md)保留为已有实现和历史验证的记录。

## 1. 目标与完成标准

采用一套共享业务、主要界面与交换格式，分别提供持续维护的 Web 入口和 Windows Tauri 桌面应用。

- **Web**：保留在线静态站及现有 Web ZIP 分发，支持免安装使用、题库整理、刷题与数据交换。
- **桌面**：首期支持 Windows 10/11 x64，增强大题库持久化、图片管理、本地文件、网络兼容和凭据保存能力。
- **业务一致性**：相同题库和答案产生相同的题型识别、判题、评分及学习记录；平台差异不改变题意。
- **数据可靠性**：迁移、保存、恢复失败不得静默丢失或覆盖原数据；两端继续读写兼容的 JSON/ZIP。
- **可持续交付**：每个阶段都保留可运行的 Web 与桌面版本，共享代码有共同回归，平台能力有独立验收。

第一轮完整改造交付包括平台适配、桌面 SQLite/媒体存储、迁移及恢复、原生文件、原生 AI/WebDAV、Windows 凭据保护、桌面兼容验证、安装包和对应检查流程。安装发布不等于本轮编写设计时已授权上传或发布制品。

| 能力 | Web 端 | Windows 桌面端 |
| --- | --- | --- |
| 题库、练习、考试、错题、收藏、记录 | 保留现有功能 | 共享业务规则与主要界面 |

| 数据存储 | 首期保留 localStorage，接入统一提交接口 | SQLite、事务与一致性恢复快照 |

| 文件读写 | 浏览器文件选择、File/Blob、下载 | 原生选择/保存、受控路径与可靠替换 |
| AI/WebDAV | 浏览器请求，遵守 CORS 与证书检查 | 受控原生请求、超时/取消和错误分类 |
| 凭据 | 保留现有记住/会话选项及浏览器存储限制 | Windows 系统凭据存储；不记住时仅存内存 |

| 离线使用 | 保留 Web ZIP 已有本地资源能力 | 已安装后的核心功能与随包文档处理离线可用 |
| 分发 | 独立发布静态站与 Web ZIP | 独立构建 Windows 安装包 |

Web 首批正式回归覆盖发布时选定的现代 Chrome/Edge 版本，记录确切版本；其他浏览器按实际验证扩展。Web 不承担 Win7 或任意旧浏览器兼容承诺。Windows 的具体系统构建号、WebView2 最低版本在发行验收矩阵中记录，不用“Win10/11”概括未经验证的全部历史版本。

本轮不包含 Win7、32 位 Windows、其他系统原生桌面包、前端框架整体迁移、Web IndexedDB 迁移、PWA/Service Worker、双向自动同步、自动更新、MinerU、完整练习/考试草稿恢复，以及托盘、开机启动、文件关联、多窗口。已有核心功能继续保留；这些新增能力按独立需求演进。

Android 原生版通过交换格式和 fixture 保持互通。本轮不重写其 Kotlin 业务，也不自动覆盖 Android Web 壳内的旧 assets。

## 3. 当前基线与差距

| 当前事实 | 对设计的影响 |
| --- | --- |
| `apps/web/app.js` 将业务集中在 IIFE 中 | 沿现有边界渐进抽取，不以模块化为由改写全部解析/评分 |
| `loadState()`、`saveSilent()` 同步读写整包 localStorage JSON | 先改初始化与提交语义，再接异步数据库 |
| 图片可能位于题干、选项、解析、images 和历史快照 | 文件化须遍历完整引用，不能只处理 images 字段 |
| 已有 Web 完整 JSON、题库 JSON 和原生兼容 ZIP | 保留转换规则与既有格式，避免另造互不兼容备份 |
| WebDAV 配置、AI Key、WebDAV 密码有独立存储项 | 迁移不能只处理主状态，也不能把凭据装入备份 |
| 本地及 WebDAV 恢复已有写入失败回滚 | 新存储必须保持并加强数据保全语义 |
| 练习/考试完整会话在内存，只有部分进度与提交结果持久化 | SQLite 接入不自动增加关闭后续考能力 |
| 桌面为 Tauri 2/WebView2 原型，权限为空，构建为无安装器 EXE | 原生能力、权限与安装均是后续实现项 |
| 资源生成已具备过滤、内联事件转换、路径安全与许可证保留 | 增加桥接时延续现有生成器与 CSP |
| Android Web 壳加载 file 来源的独立旧资源副本 | 不假定它与 Web 已同步，未来同步须单独验证 |

依据：[Web 业务源码](../../../apps/web/app.js)、[桌面说明](../../../apps/desktop/README.md)、[资源生成脚本](../../../apps/desktop/scripts/prepare-web.mjs)、[Tauri 配置](../../../apps/desktop/src-tauri/tauri.conf.json)、[Android Web 壳](../../../apps/android/app/src/web/java/com/yiqiu/shirohaquiz/WebShellActivity.kt)。

## 4. 架构与源码组织

```text
共享页面与业务（apps/web）
  题库模型、解析清洗、判题评分、练习考试、备份转换
                       │
                 平台服务契约
                 ┌─────┴─────┐
             Web 适配器    桌面适配器
             浏览器 API    本地 Tauri 桥接
                              │
                         Rust 业务命令
                   SQLite / 媒体 / 文件 / 网络 / 凭据
```

共享业务仍以 `apps/web` 为源码入口，按修改需要逐块抽离；不提前建立多包框架。现有 JavaScript 遵循现有风格，新增边界使用明确的类型定义和检查；可复用 JSDoc + checkJs，不为类型偏好整体改写历史代码。

| 位置 | 职责 |
| --- | --- |
| `apps/web/app.js` | 逐步移除平台依赖的调用细节，保留业务规则 |
| `apps/web/platform/`（新增） | 契约、浏览器实现、能力检测及初始化入口 |
| `apps/desktop/frontend/`（新增） | 桌面适配与本地桥接，不复制 Web 业务 |
| `apps/desktop/scripts/prepare-web.mjs` | 生成共享资源和桌面入口，保持来源不变、输出受限 |
| `apps/desktop/src-tauri/src/` | 按需要增加命令、存储、媒体、备份、网络与凭据模块 |
| `apps/desktop/src-tauri/migrations/`（新增） | 数据库版本迁移及校验 |
| `test/`、`apps/desktop/test/` | 共享格式 fixture、平台契约和桌面回归 |

Web 默认入口只加载浏览器实现；桌面生成入口在业务启动前注入桌面实现。公共业务不直接引用 Tauri 包、SQL、系统路径或全局 Tauri 对象，避免散布 `isDesktop` 分支。

Web 保持静态可部署。第一轮拆分优先保持普通脚本加载方式，或生成与当前入口一致的脚本；桌面适配器中的 npm 依赖构建为本地资源，不能将裸模块引用直接交给页面。现有 Pages 直接发布 `apps/web`，只有引入 Web 构建确有必要时才调整发布入口。

Android Web 壳暂维持原有资源。未来接入统一生成流程时，单独处理 file 来源、模块、Worker、Blob 下载及 Android bridge；不能仅复制更新后的网页就宣称兼容。

## 5. 平台契约与能力反馈

接口采用异步完成语义。类型定义与运行时验证共存；前端校验不替代原生边界校验。下列职责在实施计划中映射到具体文件与命令，接口不扩展成任意系统操作入口。

| 接口组 | 输入 | 输出及约束 |
| --- | --- | --- |
| 存储初始化/查询 | 查询范围、分页 | 已提交数据、修订号或明确加载错误 |
| 存储提交 | 操作 ID、预期修订号、受支持业务变更 | 新修订号；校验、冲突或写入失败 |
| 文件导入/导出 | 文件选择结果、数据范围、兼容格式 | 预览、保存结果或用户取消 |
| 媒体 | 已授权资源 ID | 受限显示资源或明确缺失，不接受任意路径 |
| AI | 已配置服务、消息、请求/题目标识、取消信号 | 非流式结果、取消或脱敏错误 |
| WebDAV | 已配置服务、限定备份操作及远端对象 | 列表、上传/恢复状态与完整性结果 |
| 凭据 | 服务绑定、设置/替换/删除、记住选项 | 保存状态，无通用明文读回接口 |
| 任务 | 任务 ID、取消请求 | 阶段、进度、终态 |

操作错误区分输入无效、存储不可用、容量不足、修订冲突、网络失败和取消，保留可供 UI 决定重试的代码；用户可见信息不含凭据、请求头或完整敏感路径。

平台入口给出原生保存、受保护凭据、PDF/OCR 等能力，页面据此展示功能。能力为“可用、不可用及原因、探测中”等明确状态，不能只依赖 UA。原生授权始终由 Rust 权限与输入验证执行。

PDF/OCR 按功能需要加载，失败只限制对应功能；首页、核心刷题和备份不能因可选库加载失败白屏。可给出升级浏览器、粘贴文本或导入现成 JSON 的替代入口，不把不完整解析标记为成功。加载用户数据失败进入恢复状态，不以空题库覆盖原数据。

## 6. 初始化、保存与并发

### 6.1 初始化状态

启动按 `loading → ready` 或 `loading → recovery_required` 推进。`ready` 前禁止修改数据；确认确实没有已有数据时才初始化默认题库。数据库故障、损坏文件或不支持的 schema 都不能被解释为“首次启动”。

内存业务状态、待提交状态和已持久化修订号分别管理。显示“已保存”必须对应完成的提交；查询失败或提交中不能先更新成功状态。

### 6.2 有序提交

单一写入队列管理当前应用会话的持久化：

1. 接受业务操作时冻结该次变更或快照，不让异步序列化读到随后修改的对象。
2. 每次提交具有操作 ID 和预期修订号；桌面事务同时记录结果与修订号，以便重试和结果查询。
3. 已完成提交再推进保存状态；失败阻止依赖该提交的后续操作继续覆盖，并保留待保存内容。
4. UI 回滚只能针对失败操作及其依赖，不能用旧全量快照覆盖已经产生的后续编辑。
5. 导入、覆盖恢复、清空数据进入排他操作：等待已有提交达到确定状态，暂停新写入，再校验并提交；取消或失败后恢复正确的写入入口。

适配初期可暂用整体快照保持业务兼容；完成桌面数据改造前，将高频写入转为按题库、题目、记录等业务单位提交，并使首页/列表按需查询，避免全库和全部图片常驻内存。

桌面同一数据目录只允许一个写入实例，锁覆盖数据库、迁移和媒体操作。Web 首期不新增多标签同时编辑支持：存储修订与变更通知用于识别外部变化，发现变化后阻止旧快照继续保存并提示重新加载；不能宣称 localStorage 修订号提供了跨标签原子事务。需要可靠的跨标签并发编辑时另行设计。

### 6.3 退出语义

桌面关闭时检查待提交数据与原生任务：完成必要提交后退出；失败保留窗口并提供重试或用户明确放弃。可取消任务在提交边界前结束，已提交结果不能被 UI 显示为“已取消”。窗口关闭不会静默继续上传。

Web 的正常操作及时持久化，不把关键保存延迟到页面卸载。`beforeunload` 只能作为受浏览器限制的提示辅助，不能承诺它会等待异步队列完成；刷新、强制关闭和进程终止应通过已经完成的提交及明确的未保存反馈控制风险。

当前练习/考试会话仍按既有规则结束和生成记录。关闭时提示未提交会话，不将“数据库已保存”解释为“可恢复未交卷考试”。完整会话快照、逾期恢复和提交幂等属于后续独立功能设计。

## 7. 桌面持久化与目录所有权

### 7.1 数据所有权

Rust 独占数据库连接、写入调度、媒体文件和恢复操作。页面保留交互所需状态，通过业务命令查询/提交，不能执行任意 SQL。

使用应用身份 `com.yiqiu.shirohaquiz.desktop` 定位正式数据目录，保持既有身份稳定。开发、正式、测试使用独立原生数据根目录与凭据命名空间；隔离覆盖数据库、媒体、临时文件、锁、恢复快照和日志。

应用安装目录、用户数据目录、缓存和用户选择的导出目标分开。题库不放入安装目录，清缓存或卸载不默认删除用户数据。

### 7.2 数据集合

| 集合 | 内容与约束 |
| --- | --- |
| 题库 | 名称、分组、顺序、元信息与稳定 ID |
| 题目 | 题库 ID＋题目 ID、排序、题型、完整兼容载荷 |
| 错题/收藏 | 保留来源题库、复习计数/时间、收藏时间和必要快照 |
| 学习记录 | 得分、答题详情和历史题目快照；删除题库不意外删除历史 |
| 设置/练习进度 | 非敏感设置、选中题库、既有续做位置 |
| 服务配置 | AI/WebDAV 非敏感端点与配置；凭据值不在数据库 |
| 媒体/引用 | 内容哈希、类型、尺寸/字节数和完整引用关系 |
| 数据库迁移/操作记录 | 内部 schema、来源摘要、幂等操作与提交状态 |

初期采用“可查询字段＋完整兼容载荷”，保留合法扩展信息；内部 SQLite schema 与外部备份版本分别管理。现有 `normalizeQuestion()` 会重建固定字段对象，不可直接当成无损存储迁移器，需对富文本、公式、图片及未知兼容字段建立保全测试。

SQLite 的事务、锁等待、耐久性和备份策略明确配置。耗时数据库/文件操作不阻塞 WebView UI；恢复快照使用一致性备份机制，启用 WAL 时不能只复制主数据库文件。

## 8. 图片与原生文件

### 8.1 图片表示和提交顺序

桌面将图片保存为应用管理的不可变资源，按内容哈希去重；数据库保存资源引用，缩略图作为可再生成缓存。原图不因性能优化被静默缩小或删除。

引用扫描覆盖题干、选项、解析、结构化 images、错题/收藏元信息与历史题目快照。UI 通过媒体适配解析显示资源；内部资源 URL、绝对路径不进入跨端导出。

文件系统与数据库没有共同事务，因此采用以下顺序：写临时媒体 → 校验内容与哈希 → 完成媒体落地 → 数据库事务提交引用和状态。失败可留下未引用文件，不能留下已提交但缺少文件的引用。

恢复替换时保留原媒体直至新数据可读。垃圾回收只处理确认无引用的应用资源，并排除恢复快照、历史记录和运行中任务；不能用“题库已删除”推断图片没有其他引用。

### 8.2 用户文件授权

原生对话框或拖放产生用途受限的文件授权，令牌绑定当前窗口/会话、用途和生命周期；取消、任务完成或会话结束后释放。Rust 校验实际来源，不把任意页面字符串当作用户授权路径。

校验文件格式、大小、实际路径、符号链接/junction 及读写目标。ZIP 处理拒绝路径穿越、绝对路径、非法链接、重复条目歧义和解压膨胀。限额使用具名配置并向用户解释，不能静默截断内容。

导出先写目标目录临时文件，校验成功后可靠替换；失败保留旧目标。覆盖用户文件必须有明确的选择/确认语义。导入预览前后不直接覆盖现有题库，用户取消选择不改变业务状态。

## 9. 两种迁移路径与恢复

### 9.1 外部 Web 到桌面

在线网站、Web ZIP 来源和桌面 release 数据互相独立。用户先在原浏览器导出完整兼容备份，再在桌面选择导入并预览；不扫描或读取浏览器 profile。保留现有站点来源、Web ZIP 启动来源和桌面身份，避免无意改变数据定位。

### 9.2 旧桌面原型升级

旧桌面 release 的同一应用来源可通过页面读取自己的 localStorage，再由迁移命令接收受校验的数据。开发来源不自动混入正式数据。

| 来源 | 处理 |
| --- | --- |
| 主状态 `shiroha_quiz_state_v28_4_c1` | 题库、图片、错题、收藏、记录、设置、跨端元信息迁入新存储 |
| 独立 WebDAV 配置 | 迁移非敏感端点、账号和目录等配置，标明需要验证的凭据绑定 |
| AI/WebDAV 持久凭据 | 用户选择迁移后写入系统凭据存储；验证成功后才移除对应旧值 |
| 会话凭据 | 仅在当前会话按用户选择转移；不自动升级为长期记住 |
| 旧状态键与无法识别内容 | 保留并报告，不批量清除或擅自猜测其语义 |

迁移阶段为：检查来源和目标 → 保全不含凭据的恢复快照 → 暂存媒体 → 事务写入 → 核对关键数量、ID、内容及引用 → 同事务提交迁移标记 → 重启读取验证。

来源摘要和迁移标记使重复执行可识别，不能重复导入。同名或同 ID 冲突遵循现有兼容恢复规则并显示预览。目标已有桌面数据时，不进行隐藏覆盖。

取消、磁盘满、权限失败、损坏输入或崩溃都必须保全旧数据。迁移成功后以 SQLite 为唯一活动来源，不双写；旧数据按明确操作清理，不迁完主状态就删除全部配置和凭据项。

数据库损坏或 schema 过新时进入恢复流程，不能回退旧 localStorage 后继续写入产生分叉。降级程序与降级数据分别处理，未经支持的旧版本不能写新 schema。

## 10. 统一交换格式与 WebDAV 备份

继续使用既有题库 JSON、Web 完整备份 JSON、图片 ZIP 和 Android 原生兼容 ZIP。完整备份与选中题库导出明确区分；不能将仅题库文件宣传为完整学习数据备份。

共享转换层维护题型别名、多空答案、稳定 ID、分组、富文本、图片、错题、收藏和记录。内部 SQLite/浏览器结构不成为外部协议；合法扩展字段保全，不支持的版本明确拒绝或提示，不能静默丢弃。

所有导出采用同一套敏感字段排除规则。非敏感设置使用白名单，凭据、系统凭据引用、绝对路径、缓存和日志不进入备份。恢复服务端点后不能自动绑定本机旧凭据。

恢复先解析/校验并预览，再进行合并或覆盖。操作与保存队列互斥，媒体和数据库按受控顺序提交；失败保留原库和已存在备份。SHA-256 用于检测内容完整性，不代表备份来源已获授权。

桌面覆盖恢复或数据库 schema 升级前，必须成功建立并校验本地恢复快照，保全一致的数据库状态及其引用媒体。媒体可通过保留不可变资源与引用实现保全，不能只记录文件名而不保留资源；快照创建或校验失败时停止覆盖或升级，保留当前数据。

WebDAV 首期继续使用现有完整 JSON、历史文件命名与 `latest.json` 协议，保留哈希校验和人工恢复确认。区分“历史备份上传成功但 latest 更新失败”的部分成功状态；重试先核对远端结果。

两端可使用同一 WebDAV 服务作为手动备份/恢复渠道，但本轮不引入自动双向同步、后台上传或远端自动清理。图片 ZIP 云备份若要扩展现有协议，先统一两端 reader/writer 和恢复语义。

## 11. 原生网络与凭据

### 11.1 业务请求边界

Web 适配保持浏览器 fetch、CORS 和证书检查；桌面 Rust 提供限定 AI/WebDAV 业务操作，不开放任意 URL、任意方法、任意文件路径和鉴权头的通用代理。

首期 AI 保持现有非流式响应、限定错误条件下的格式降级、取消、请求 ID、题目指纹与迟到响应隔离。AI 内容仍是待人工核对的建议，用户确认后才写回题库。网络替换不改变现有判题规则。

桌面保留用户明确配置的本机模型和自定义服务。优先 HTTPS，明确配置的本地/内网 HTTP 按用途处理；不关闭 TLS 验证。端点由原生层校验；重定向逐跳检查，禁止向不同来源泄露认证头。WebDAV href 必须仍位于配置来源和远端目录范围。

超时、取消、鉴权失败、限流、证书错误、响应过大和结果不确定有独立错误语义。AI 等可能产生费用的请求不进行不透明重试；本轮仅提供用户触发的请求，数据发送范围限于当前操作需要的消息或备份。

### 11.2 凭据生命周期

桌面使用 Windows 系统凭据能力，由 Rust 读写；未记住时仅保留在进程内存。Web 凭据由浏览器适配器按现有选项管理，不宣称已具备原生加密保护。共同界面提供输入、替换、删除和保存状态，不提供通用明文读回。

凭据绑定服务类型、规范化端点和账号，不仅绑定配置 ID。端点或账号变化后必须重新输入或由用户明确重新绑定；备份恢复不能直接建立凭据关联。取消“记住”要清除先前持久副本，删除失败明确报告，不能假报成功。

旧凭据迁移成功并验证后才清除旧值，失败保留供重试。日志、错误、备份和测试报告不得包含凭据。系统凭据保护不表述为能抵抗同一用户下任意恶意进程的完全隔离。

## 12. IPC、CSP 与任务生命周期

桌面仅允许主业务窗口调用批准的业务命令，远程页面不获得原生能力。自定义命令与插件权限分别配置，不能因为 capability 当前为空就推断新注册命令自动被限制。按官方机制显式约束命令清单、窗口范围和参数。[Tauri capability 文档](https://v2.tauri.app/security/capabilities/)

保留 `withGlobalTauri: false`，生产可执行脚本仅来自本地；不通过远程/内联 JavaScript、JavaScript eval 或关闭 CSP 修复兼容。WASM 编译权限不扩大为任意脚本执行。用户题库、富文本、图片与导入文档视为不可信输入，沿共享清洗规则处理，原生层继续验证安全边界。

媒体资源访问只覆盖应用媒体目录；外链通过受控浏览器打开方式处理，不允许主窗口任意导航。资源生成仍在清理前验证目标、拒绝源/目标重叠和链接越界，并保留第三方许可与离线资源。

长任务采用 `queued → running → succeeded / failed / cancelled`；恢复等任务在 running 内明确暂存、验证、提交阶段。进度事件带任务 ID 与必要阶段信息，不包含凭据或完整正文。

取消在提交前生效，释放 worker、临时文件与网络请求；提交开始后以事务结果为准，不能显示取消却已写入数据。结果不确定时通过操作 ID 查询，不能盲目重复写入。关闭窗口按第 6 节协调任务与保存。

现有 `config.test.mjs` 的“零原生权限”测试在接入能力时改为“只有批准命令和范围可用”，保留固定应用身份、脚本边界及拒绝通用高权限接口的断言；不删除有效安全检查。

## 13. 文档处理、性能与桌面交互

继续复用现有 PDF.js、Tesseract、MathJax 和 ZIP/OOXML 解析。采用随包本地资源，按功能加载；完整验证 DOCX/XLSX、公式、文字 PDF、中文扫描 PDF 和导入/导出链路。英文 Canvas OCR 不替代中文扫描 PDF 验收。

PDF/OCR 按页处理，限制并发、像素、输入体积及响应大小；既有业务限额先保持，调整须有测量依据和具名配置。处理完成/取消后释放文档、Canvas、ImageBitmap、Blob URL、Worker 和临时文件。大文件避免在 JS/Rust 之间反复复制全量 Base64；必要时分块或转为受控任务。

桌面保留单窗口，完善原生打开/保存、窗口尺寸与位置恢复、应用内快捷键、保存反馈和退出处理。拖放接入统一导入管线，验证与现有 HTML 拖放的关系；不只翻转 Tauri 配置开关。

共享界面支持键盘、可访问名称、焦点管理、异步错误反馈和 reduced-motion。平台差异在设置或相关入口说明，例如“保存到浏览器”与“保存到本机”，不向普通用户暴露内部数据库和 IPC 细节。

性能使用固定题库、图片库和 PDF 样本，对比同机同配置的启动、交互、导入峰值及资源释放。复用 benchmark，区分工作集、私有提交和 OS 缓存，统计完整进程树；不预先承诺固定内存降幅。

## 14. 构建、发行与依赖

Web 静态站、Web ZIP 和桌面安装包分别产出，共享业务源码只有一份。桌面前端随安装包发布，不在启动时加载网站替换本地业务代码。发行记录包括共享源码版本、平台版本与交换格式版本。

桌面保留已有 EXE 构建入口，增加独立 NSIS 安装构建；安装以普通用户场景为优先，产品版本在 npm、Cargo 和 Tauri 配置间一致。验证原型到安装版的数据连续性，卸载默认保留数据。

普通安装与真正离线安装分别配置和验收 WebView2 部署；“已安装后可离线”不等于“无网络也能安装”。支持系统、运行时下限、安装依赖、签名和升级路径以实际制品测试为准。[Tauri Windows 安装说明](https://v2.tauri.app/distribute/windows-installer/)

第一轮提供人工下载并安装的新版本升级路径，验证覆盖安装和数据迁移；自动更新单列后续阶段。签名材料、发布端点与上传操作在发行阶段处理，不将设计确认解释为 commit、push、购买证书或发布授权。

沿用 npm、Cargo、现有 Rust edition 与锁文件。实现时按需要选用 SQLite、HTTP、Windows 凭据封装和官方桌面插件；依赖加入前说明必要性、维护状态、许可兼容性、体积与版本要求。SQLite 只通过原生业务接口访问，即使选用支持前端 SQL 的库也不开放任意执行权限。

新增 Windows CI 负责类型、lint、测试和构建，GUI 测试放在具备实际条件的 Windows 环境。现有 Pages 工作流不代表已具备桌面 CI。新文档和新模块同步纳入检查范围，生成资源不手工维护。
