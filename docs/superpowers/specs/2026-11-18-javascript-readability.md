# 函数注释、长代码块、正则与空行治理方案

方案已于 2026-11-18 获确认。首期覆盖项目手写 JavaScript，沿用现有 ESLint 对 Web、桌面、脚本和测试的文件识别及排除范围。Rust 可沿用业务注释与按职责拆分的原则，专属检查另行评估。实施顺序见[实施计划](../plans/2026-11-18-javascript-readability.md)。

## 四条编写约定

| 约定 | 建议口径 | 验收方式 |
| --- | --- | --- |
| 超过三行的函数加注释 | 函数体从第 4 个有效代码行起，在定义上方用中文说明它解决什么问题，以及调用方需要知道的边界。已有清楚的描述可直接复用。声明、对象方法、类方法和箭头函数（含回调）统一处理。 | ESLint 检查位置和有无说明，审查者核对描述与行为。 |
| 过长的代码块封装为函数 | 建议以单个逻辑块超过 20 个有效代码行为拆分审查点。优先提取能单独命名、说明输入和结果的步骤；较短的块若混合独立职责也可拆。保留同一状态转换、事务或错误处理所必需的上下文。 | 超过阈值时给出抽取方案，确需整体保留的在审查中说明原因。 |
| 使用正则时说明用途 | 在正则字面量、`RegExp(...)` 或 `new RegExp(...)` 的定义处说明匹配什么、用于哪项判断或转换。简单正则一句即可；有捕获组、边界或易混格式时，用一个输入例子说明。命名正则由多处引用时在定义处说明一次。 | 用语法树识别正则及全局构造器调用。人工核对用途，避免只写“匹配正则”或复述符号。 |
| 逻辑块或方法结束后空一行 | 完整的条件、循环、`switch`、`try` 或函数结束后，若还有同级语句，两者之间恰好留一个空行。相邻的类方法、对象方法也按此排版；下一项有前置注释时，空行放在注释之前。 | 检查相邻语句或成员。复合结构内部的 `else`、`catch`、`finally`、`do … while` 保持相连；父块闭合前和文件末尾沿用已有规则。 |

**有效代码行**按函数体或逻辑块内含代码的物理行计算。签名、空行、纯注释行和仅含括号、逗号或分号的结构行跳过；代码行带行尾注释仍计一行。表达式体箭头函数按其表达式计数。按这个口径，三行以内的函数如果涉及兼容行为或状态约束，仍应遵循项目已有的注释要求。

函数说明紧贴它所修饰的声明、属性或回调；已有 JSDoc 可以在类型标注前补一句业务说明。正则写在链式调用里时，可将说明放在所属调用上方；同一表达式有多个不同用途的模式时，分别说明。空行也按完整语句处理，例如赋给变量的箭头函数结束于整条声明，传给 `forEach` 的回调结束于整个调用。无需在参数列表里插空行。

## 首批试点：练习题号解析

[练习模块](../../../apps/web/training.js)的 `parsePracticeNumberRangeV58916` 有一段遍历输入片段的回调，同时识别格式、校验范围、收集索引和记录错误。建议这样处理：

1. 给入口补上调用方关心的说明，例如“把用户填写的题号转换为去重、升序的零基索引。任一片段无效时，整次选择返回错误。”
2. 提取“解析并校验一个题号片段”的函数，让单号和闭区间都得到有效起止值，或返回无效结果。主函数保留错误汇总、去重与排序。保留现有的输入分隔方式和错误文案。
3. 给区间正则写用途，例如“识别 `2-4`、`2~4`、`2—4` 和 `2至4`，取出首尾题号供范围校验。” 分隔输入、识别单号的正则也各自说明用途。
4. 在输入为空的提前返回分支之后留一个空行，再建立结果集合。将辅助函数与主函数用一个空行隔开。这样的空行直接标出校验结束和下一步开始的位置。

首批行为验收使用[练习回归](../../../test/dual-platform/training.test.cjs)。题量为 5 时，已有用例要求 `3,1-2,2` 得到 `[0, 1, 2]`，`5-4` 得到空索引及原错误文案。实施时先补 `1,6` 的混合输入边界，锁定其中一项越界会使整次选择失败，再抽取函数。

## 落地顺序

1. **记录现状。** 复用[共享 ESLint 配置](../../../apps/desktop/eslint.rules.mjs)的文件范围，生成只读的逐文件报告，分别统计缺函数说明、长块、缺正则说明和缺空行。现有 5 个模块已执行 120 行函数上限；现有全局 Stylistic 规则已限制连续空行和块内首尾空行。报告用来选择迁移批次。
2. **验证规则边界。** 优先复用已锁定的 Stylistic 语句间距与类成员间距规则。让正反例检验覆盖面，对函数说明、正则说明、对象方法等缺口再补项目内 ESLint 规则。样例至少覆盖 3 行与 4 行、无说明与已有说明、正则字面量与动态构造、相邻方法、提前返回分支、连续分支和文件结尾。只有空行可自动修复，注释与函数拆分由人编写。
3. **试点后逐文件启用。** 先用上述解析函数审查阈值和示例，再处理同文件其余命中。整文件通过才加入强制检查名单；后续按业务模块扩展。规则实现与修改进入现有全量、暂存区和 CI 检查路径，并在[规则回归](../../../apps/desktop/test/lint-config.test.mjs)中验证桌面与仓库根两套配置入口。确认后的日常写法归入[JavaScript 风格指南](../../../rules/javascript-style-guide.md)。
4. **分开验收格式和行为。** 规则阶段在 `apps/desktop` 运行 `pnpm run lint:fixtures`、`pnpm run lint`、`pnpm run typecheck` 与 `pnpm test`。抽取题号解析时先在仓库根运行 `node --test test/dual-platform/training.test.cjs`，再按[项目验证要求](../../../AGENTS.md)检查桌面复用资源。每批记录涉及文件、四类命中变化和实际通过的检查。
