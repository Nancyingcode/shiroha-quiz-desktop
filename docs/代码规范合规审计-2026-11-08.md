## 3. 详细说明

### F-01 重复书写 harness 模式判定（高）

位置：`apps/web/app.js:378`、`apps/web/app.js:396`、`apps/web/app.js:675`、`apps/web/app.js:959`、`apps/web/app.js:968` 等 10 处。

现状：同一条件 `config.execution?.mode==='harness'` 在多个函数中重复出现，且其中若干处还伴随 `configured` 组合判断，例如：

```js
if(provider)provider.textContent=configured||config.execution?.mode==='harness'?aiExecutionLabelV99(config):'未配置';
```

违规条款：规则 1（重复出现的复杂条件必须提取为具有业务语义的变量）、规则 4（状态变化伴随其他字段变化时共享同一业务条件）。

风险：后续新增执行模式（例如 `cli`、`local`）时，只需遗漏一处就会出现标签、隐私提示、预览计数与请求构造不一致。

建议修复：在配置读取层提供语义化判定，所有调用点复用：

```js
const isHarnessMode = config.execution?.mode === 'harness';
const isAiReady = configured || isHarnessMode;
```

### F-02 AbortError 判断与文案条件分别复制（高）

位置：`apps/web/app.js:1120`。

现状：

```js
const silentAbort=error?.name==='AbortError'&&aiImportSilentCancelV99;
const message=error?.name==='AbortError'?'AI 整理已取消，现有识别结果未被修改。':(error.message||'AI 整理失败，现有识别结果未被修改。');
```

违规条款：规则 4。同一判断写两遍，改一处必漏另一处。

建议修复：

```js
const isAbort = error?.name === 'AbortError';
const silentAbort = isAbort && aiImportSilentCancelV99;
const message = isAbort
  ? 'AI 整理已取消，现有识别结果未被修改。'
  : error.message || 'AI 整理失败，现有识别结果未被修改。';
```

### F-03 嵌套三元内混入默认值（中）

位置：`apps/web/app.js:957`。

现状：

```js
batch.value=String(resetScope?(mode==='analysis'?AI_ANALYSIS_DEFAULT_BATCH_V991:AI_REVIEW_DEFAULT_BATCH_V991):(current||(mode==='analysis'?AI_ANALYSIS_DEFAULT_BATCH_V991:AI_REVIEW_DEFAULT_BATCH_V991)));
```

违规条款：规则 2（避免复杂或多层嵌套三元表达式）。

建议修复：

```js
const defaultBatch = mode === 'analysis' ? AI_ANALYSIS_DEFAULT_BATCH_V991 : AI_REVIEW_DEFAULT_BATCH_V991;
batch.value = String(resetScope ? defaultBatch : (current || defaultBatch));
```

### F-04 catch 分支三层三元承担多重职责（中）

位置：`apps/web/app.js:1053`。

现状：一个三元表达式同时决定状态文本、通知 tone、以及是否拼接已完成计数，嵌套两层。

违规条款：规则 2。

建议修复：改为 `if/else`，或抽出 `describePreviewError(error, processed)` 纯函数返回 `{ message, tone }`。

### F-05 未命名的复合布尔（中）

位置：`apps/desktop/frontend/harness.js:502`。

现状：

```js
const result = {...current, busy: operationBusy() || active.size > 0 || pendingMutations > 0 || selectingAdapter || selectingModel};
```

违规条款：规则 5（条件变量应描述为什么发生、具有业务语义）。

建议修复：

```js
const hasActiveWork = active.size > 0 || pendingMutations > 0;
const isSelectingRoute = selectingAdapter || selectingModel;
const isHarnessBusy = operationBusy() || hasActiveWork || isSelectingRoute;
```

### F-06 同一业务状态存在两套判定（中）

位置：`apps/desktop/frontend/harness.js:569` 与 `apps/web/app.js:396`。

现状：前端用 `input('ai-execution-harness')?.checked ? 'harness' : 'api'` 判定执行模式，Web 层用 `config.execution?.mode` 判定。同一业务状态有两条独立来源。

违规条款：规则 6（状态流转持续增加时应集中为显式状态转换逻辑）。

建议修复：表单只做输入采集，模式判定统一由 `resolveExecutionMode(config, formState)` 计算并由两侧共用。

### F-07 模块级可变标志承担状态机职责（中）

位置：`apps/web/app.js:10101`。

现状：

```js
try{result=action()}finally{enteringMutation=false}
```

该标志在模块级可变，控制写入互斥，但没有生命周期、所有权与重置说明。

违规条款：规则 6、注释规范第 10 条（状态机等非显然逻辑必须说明设计约束）。

建议修复：改为显式互斥对象（含 `enter/exit/isEntering` 与重入计数），或补充设计约束注释说明「为何必须模块级、何时重置」。

### F-08 生产路径 unwrap（高）

位置：`apps/desktop/src-tauri/src/commands.rs:459`。

现状：

```rust
authorize_source(label, &url::Url::parse(source).unwrap())
```

违规条款：仓库 `AGENTS.md` 4.2——外部输入和可恢复失败使用 `Result`，不得靠 `unwrap`、`panic!` 或默认值掩盖错误。

说明：其余 18 处 `unwrap` 均位于 `paths.rs`、`tasks.rs` 的 `#[cfg(test)]` 内，属合规用法。

建议修复：

```rust
let source_url = url::Url::parse(source).map_err(|_| Error::invalid_argument(label, "source"))?;
authorize_source(label, &source_url)
```

### F-09 lint 覆盖缺口（中）

位置：`apps/desktop/eslint.config.mjs:6`、`apps/desktop/scripts/lint-platform.mjs:10`。

现状：`eslint.config.mjs` 仅匹配 `**/*.mjs`；`lint-platform.mjs` 只纳入 `apps/web/platform/**`、`apps/web/training.js`、`test/dual-platform/**`、`apps/desktop/frontend/**`。`apps/web/app.js` 不在任何 lint 覆盖内，而它是 F-01 至 F-04 的集中地（116 行超过 400 字符、62 处嵌套三元）。

违规条款：`AGENTS.md` 第 6 节——能通过 lint 执行的约束优先自动化，避免只有文字要求而没有可运行验证。

建议修复：新增 `apps/web/app.js` 的渐进式 lint 配置（先只开 `no-var`、`no-nested-ternary`、`max-len`、`prefer-const`），避免一次性全量报错阻塞门禁；同步更新 `lint-platform` 的文件清单与文档描述。

### F-10 关键规则只对 .mjs 生效（低）

位置：`apps/desktop/eslint.config.mjs:6`、`12`。

现状：`no-var`、`prefer-const`、`no-unused-vars` 挂在 `files: ['**/*.mjs']` 上，`.js` 源码不受约束。

建议修复：与 F-09 合并处理，按目录分批放开 `.js` 覆盖。
